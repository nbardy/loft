# Lane 2.4: library (19 Nov 2026)

Plan: `docs/proposals/2026-11-19_lean_rust_loft.md` §1.4, §3.2, §8.1, §8.2 (lane 2.4). Branch `feat/lr24`, base `7b0cc53`.

## What

- **`graphFn(name, params, body)`** (`src/record/graph_fn.ts`, exported from `src/core.ts`): a TypeScript function of
  expressions is recorded once over binders, and each call becomes one `Call`. The rule for when a call is recorded is
  the same as for text functions (`src/text/lower.ts`): every argument must be a non-constant expression and no
  identities may be open. Otherwise the call is inlined. The TS engine still reads every call inlined, uncounted, so
  its output does not change. A graph function of a graph function is that same function, so `surface` and
  `mapNormal` share one recording.
- **Recorded surface maps.**
  - `draw.surface` records the surface's `point`, `normal` and `anchor` as graph functions, so the vertex stage, the
    rest measurement, each copy and the constructor's own type check are all calls.
  - `surface()` and `mapNormal` record the map, so a normal is four calls rather than four copies of the map.
  - The ship recipe (`examples/recipes/hull.ts`) records its skin and its two edges, which the deck, both bulwarks
    and the normals all read.
- **Symbolic `gridDetail`.** The rest measurement is one point over `(loft_grid_s, loft_grid_t)`, evaluated at the
  5 × 5 `restPoints` and at `REST_CENTRE`. Before this it was 25 constant copies of the surface plus the anchor.
- **FilledTable is deleted.**
  - Supplied numbers are a `DataTable { data }`: meshes, bricks, copies, static `tabulate` and sculpt layers. The
    sculpt layer's slopes are worked out once into its bytes, and `SculptTable` is gone.
  - A recurrence's four tables are a `RecurrenceTable { recurrence }`.
  - The `cpu` table program and `TablePrep` have no producers left, so they are deleted.
- **Medium fills as maps** (`src/soft/medium.ts`). Media of more than two clusters sort along the same Morton curve
  as before, now in maps:
  1. the box of the centres;
  2. 10-bit keys per axis, interleaved and stored as two 15-bit halves so that f32 holds them exactly;
  3. ranks, with ties broken by index;
  4. the sorted blob table, with the light pass shared with the small path;
  5. a sphere per cluster.
  `storm`, `open` and `stormfront` now build to files. Before, `loft build` refused them with "2 table(s) are filled
  by JavaScript". This is the deliberate refusal change that §2.2(c) asks to be listed.
- **The job print walks call arguments lazily** (`src/record/print.ts`): an argument is walked at its binder's first
  read, because the TS graph meets it there. Before this, `compute_frame` printed unequal with only the numbering
  different. **loft-ir's printer must do the same.**

## Left

- **The 13 measure checks are classified, not yet rewritten as formulas.** They still run as TS samplers. The
  rewrite needs the Rust `Check` and `Formula` (lane 2.3) to land on. Without them it would be TS code that wave 2
  deletes.
- **`graphFn` on `lib/{noise,fold,sdf*}` and the light terms is not applied.** Profiling shows them absent from the
  hot list: for Titan, heron_leap and stormfront, R is surfaces, tables and `grad`. The next lever is the bound
  table's constant anchor (`grid_detail.ts`, `anchorOf` "one"): about 93k on Titan and 47k on stormfront. It needs
  constant arguments recorded as Calls, which in turn needs a fold in the shadow print.

## Integrator notes

- No registrations are needed in rust/Cargo.toml, loft-core lib.rs or main.ts.
- **The loft-ir canonical printer must bind call arguments lazily**, as `print.ts` now does, or the Rust half of the
  shadow check will differ on any call with a leaf argument.
- Graph functions are now everywhere on the wire, with 1,003 Calls in the corpus. Each body is one `Fn` decl, and
  bodies call other bodies, so Rust's inline must handle nested Calls.

  - `tests/soft.render.test.ts`;
