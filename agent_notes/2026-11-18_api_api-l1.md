## The user's code

```ts
const fx = wgsl`
struct Grain { at: vec3f, radius: f32, colour: vec3f, opacity: f32 }
fn grain(i: f32, t: f32) -> Grain {
  let q = flight(i, t);
  let size = hash22(vec2(i, 111.0));
  let coarse = size.x * (size.x * size.x);
  return Grain(q.at, mix(0.0019, 0.012, coarse), mix(vec3(0.55, 0.18, 0.063), vec3(1.0, 0.56, 0.25), size.y), mix(0.18, 0.65, coarse) * q.fade);
}`;
draw.specks("grains", 100_000, fx.grain, { stretch: 0.004 });
const reeds = wgsl`fn spine(m: f32, k: f32) -> vec3f { return vec3(k * 0.7 - 2.0 + m * m * (sin(time + k) * 0.5), m * 3.5, select(-0.3, 0.3, k % 2.0 != 0.0)); }`;
strand({ name: `reed${k}`, spine: (m: F) => reeds.spine(m, k), ... });
```

## Pass/fail checks, measured

1. **Same graph.** Five probes (the brief's line, spray flight + grain slot, the boot field, volume_dust `folded`,
   march's 9-state loop) and six example functions (dust, emission, ground, boot paint, stormwing wing, reed spine):
   **11/11 the same structural hash and byte-identical emitted WGSL**, each form in a fresh process. Plus
   reeds_shadow's whole built artefact byte-identical. Two normalizations of the call-form side, stated in
   `tests/text.probes.ts`: constant vectors as arrays, and volume_dust's JavaScript-unrolled loop as `iterate`.
2. **Twin vs GPU** on a paint using every new op and lowered builtin (20 outputs, 153 samples incl. round's ties):
   **worst 6.4e-7** (bound 3.9e-3). Enclosures of the 13 ops hold the twin in 69,888 comparisons.
3. **Raw with its reason**: 13 fixtures (u32, i32, dpdx, fwidth, while, loop, &, hex literal, f16, frame, switch, a
   module variable, textureLoad): each is raw with `raw function f at <file>:<line>: <reason>`, renders as a library
   call, and the twin and a ranged check refuse it quoting that text.
4. **Speed**: a 307-line, 34-function module parses and lowers in **4.2 ms median, 10.0 ms cold** (target 20 ms).

## Where I went off the design, and why

- **`vec3(0.1, 0.2, 0.3)` of constants is one constant node** (the call form's `[0.1, 0.2, 0.3]`). The call form's
  `vec3(0.1, 0.2, 0.3)` is another graph of the same value (a vector node of scalar constants, emitted as a `let`), so
  "text and call form are the same graph" holds against one of the call form's two spellings. Making `vecOf` fold
  all-constant parts would unify them but changes ~230 call sites' WGSL text; not done in this wave.
- **Byte identity needs the same construction order** (WGSL names values by node number). Text naturally follows JS
  argument order; the one gap is the call form's n-ary `mul(a, b, c)`, which evaluates `c` before the first product.
- **The early-return check is WGSL's syntactic rule**, not the flags' boolean algebra.
- **A raw function reads `time` and holes through added parameters** (`loft_h<k>`) rather than L6's rewrite to
  `frame.time.x` and generated accessors: it needs no scene binding, so rung 2 works now in any shader stage. L6 can
  keep this or replace it.
- `ShadeFields` is not a prelude struct yet (only `PaintAt` and `Ray`); `fbm2`/`fbm3` are not in the prelude (option
  records).

## Review (18 Nov 2026, before merge)

Re-measured on this branch: `pnpm typecheck` clean; `tests/text.test.ts` 6/6 (11/11 probes same hash and byte-identical
WGSL; 300-line module median 5-8 ms; 69,888 enclosure comparisons); `tests/text.gpu.test.ts` worst 6.39e-7;
`expr`, `expr.eq.gpu`, `grad.fd`, `ranged` 18/18. Built from the merge base and from this branch: `reeds_shadow`'s
artefact is byte-identical; `stormwing`'s differs (the constant-vector spelling) and renders the same pixels (`three`,
640x400, `rgba d2efedfaa59eb726` both). A scene with a raw u32 PCG paint reading a param hole and `time` renders, and
`--param` changes its pixels.

Fixed in review:
- **Duplicate and type-named declarations were never refused.** The checking helper in `src/text/index.ts` was named
  `declare`; Bun's TypeScript transpiler drops a statement beginning `declare(` as an ambient declaration, so a second
  `fn f` silently replaced the first. Renamed (`claim`), commented at the site, and tested.
- **Builtins whose name continues with a digit** (`pack2x16float`, `unpack4x8unorm`) and `ldexp`, `frexp`, `modf`,
  `determinant`, `transpose`, and matrices other than 2x2/3x3 were "unknown name" errors; they now make the function
  raw, as the design says of everything outside the subset.
- A struct constructor's TypeScript-side errors pointed at line 0; they point at the struct's declaration.

Still open (not fixed here): check 1 holds against call forms with constant vectors written as arrays. Real call forms
write `vec3(0.1, 0.2, 0.3)` (spray_burst, volume_dust, stormwing), which text cannot reproduce, so a migrated example
with such constants changes its artefact bytes (not its pixels). The unifying fix (fold all-constant `vec` in `vecOf`)
changes every such artefact's WGSL and is the integrator's call. Integer arithmetic on loop counters (`i / 2`) is a
lowering error with a fix, not a raw function: the classifier cannot see types.
