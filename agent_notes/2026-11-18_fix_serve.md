# Fix lane: `loft serve` (D10, and D7 in the protocol), 18 Nov 2026

Brief: `agent_notes/2026-11-18_plan_review/fixes/serve.md` (in the main checkout); defects from `CONSOLIDATED.md` §3.
Branch `fix/serve`, worktree `~/git/_wt/loft-fix-serve`, left uncommitted for the reviewer.

## What was wrong

- Requests had no `params` or `inputs` (`serve.ts` drew every frame with `params: {}, inputs: {}`), so a witness at a
  param setting could not be rendered.
- `readBundle` parsed the manifest and read every file it named before `--check` saw anything: no size bound, no
  name check (a chunk named `../outside` read `wgsl/../outside.wgsl`), symlinks followed.
- A scene request built into `<out>/artefact`; two requests in flight with the same `out` shared that directory and
  the frame names `<k>.rgba`.
- Pending requests were unbounded (only compiles were limited).
- The compile child had no deadline; a child killed by a CPU limit (SIGXCPU) was answered as exit 1 `internal`.
- On device loss the request that noticed it was answered and the process exited 6; every other request in flight got
  end of file.
- D7: answers carried no tier.

## What changed

- `src/cli/verdict.ts`: a new verdict `budget`, exit 7, `loft: budget: <the limit>`. Not a verdict on the scene.
- `src/host/files.ts`: `readBundle(dir, limits = ARTEFACT_LIMITS)`. Before any WGSL or bin byte is read it checks,
  by `lstat`: `wgsl/` and `bin/` are real folders; the manifest is a regular file within `manifestBytes`; it is a JSON
  object of the right format and version with list `chunks`/`blobs`; every name is one plain file name (no `/`, `\`,
  `.`, `..`, NUL), named once, a regular file (no links); each bin's declared size equals its file; file count and
  total bytes within `files` and `bytes`. Reads re-check the size (a file that grew after its `lstat` is refused).
  All failures are `LoadError` (exit 3, also for `render --artefact`, which used to say `internal`). Defaults: 64 MiB
  manifest, 65536 files, 1 GiB total.
- `src/cli/args.ts`: `serve` takes `--pending N` (default 64), `--compile-seconds S` (default 120) and
  `--limits manifest=BYTES,files=N,bytes=BYTES` (any subset).
- `src/cli/serve.ts`:
  - `params` (`{name: number}`) and `inputs` (`{name: number | number[]}`) are parsed and typed at the boundary and
    checked against the manifest before the draw (unknown name, `time`, replay step inputs, wrong component count:
    `usage`, naming what the scene has).
  - A scene builds in `mkdtemp($TMPDIR/loft-serve-build-*)`, removed after its answer; `<out>/artefact` is gone.
    Each request reserves its `out` before its first await; a request whose `out` equals or nests with one in flight
    is refused (`usage`, naming the holder). Frames still go to `<out>/<k>.rgba` (creative's client checks that path).
  - A request arriving while `--pending` are unanswered is refused at once as `budget`.
  - The compile child is killed at `--compile-seconds` and answered `budget`; a child ended by SIGXCPU (or exit
    128+24 from a wrapper that does not exec) is `budget`; other signals stay `internal`.
  - Device loss is watched on the device's `lost` promise (only the current device: a transient retry destroys the
    one it replaces on purpose). `closeWith` answers every admitted, unanswered request, kills compile children, and
    exits after stdout drains. The compiler-witness exit uses the same path.
  - Every answer carries `tier: "C"`.
- Docs: `docs/handoff_training.md` "loft serve" (params/inputs, ownership, limits, budget, tier and "training never
  promotes tiers within a run", what stays the host's policy), exit 7 rows in `docs/errors.md` and `README.md`.
  `docs/api.md` is unchanged (`bun src/cli/main.ts api | diff - docs/api.md` is empty): no public export changed.
- `src/host/cache.ts`, `src/host/headless.ts`: no change needed.

## Left undone, and why

- Not verified on Linux/Vulkan or inside creative's confinement (bwrap); `ulimit -t` on macOS only. Build 2 of the
  consolidated plan covers that.
- The deadline kills the direct child. A `--confine` wrapper that does not `exec` (or forward SIGKILL to its group)
  leaves the build running after its `budget` answer. Documented; the fix belongs to the wrapper.
- No deadline on draws (a stuck GPU job): the caller kills and restarts the server, as creative's `DRAW_SECONDS` does.
- Manifest structure is checked for what decides reads (format, version, chunks, blobs, sizes). The rest (pipelines,
  bind groups) is still trusted to `loadBundle` and Dawn's validation, as before.
- Request lines not yet read from stdin when the device is lost get no answer (they were never admitted).
- Output bytes are bounded only by `times x size`; no separate `out` byte limit.
- Creative's client treats exit 7 as `RuntimeError('loft serve: ...')` (its `case _`); it will want a branch for
  `budget` when it adopts `--compile-seconds`. Its pinned fields (`ok`, `exit`, `line`, `frames[].file`/`sha256`, the
  ready line) are unchanged; `tier` is additive.
