# A renderer its author can change

Render and light, Step 2 · 19 November 2026 · design proposal

## What the consumer writes

Put a brass washer in front of a white card. Widen the hole. More card should be visible through it, more sunlight should reach the card, and the hole should widen in a mirror. Picking through the centre should return the card. All four changes ought to follow from editing one radius. Now deliberately close the hole **only in the shadow** for a woodblock print. That should take one edit at the lighting call site. Both edits matter. The first establishes that different observers can share geometry. The second establishes who owns that decision.

These are proposed TypeScript scene modules and edits. TypeScript records a composition, Rust compiles it, and wgpu runs it. The token counts below use `o200k_base`, over each complete fenced body including imports where shown, excluding the closing newline. The first and last are complete scene modules. The three middle examples are edits in a consumer's project, with their dependencies stated. The source behind every import ships with the library. The counts measure what the consumer writes for the indicated task.

**1. Stage the picture.** A scene module chooses an engine as an ordinary import. `studio` supplies its own camera, ground, area light and film. Its arguments are objects to photograph. A program that wants just the objects can import them independently. The brass values include a scattering law usable by both direct lighting and the reference integrator.

```ts
import { studio, torus, brass } from "loft/examples/studio";
export default studio([torus(1, 0.2, brass)]);
```

**2. Replace the geometry.** Here is an entire local intersection for a two-sided, zero-thickness annular plate at local z = 0. It is a deliberately simpler machining profile than the rounded torus. `surface` takes a conservative local bound, an intersection function and a material. `wgsl` parses this supported subset into the maths graph. `Ray`, `hit` and `miss` are names supplied in its typed prelude, available to other consumers. `hit` takes the ray parameter, outward normal and chart coordinates. Sign and side at the interaction remain available to the material. The scene places this plate by translating it, just as it places a mesh.

```ts
import { surface, box, wgsl } from "loft/render";
import { brass } from "loft/examples/studio";
export const washer = surface(box([-1,-1,-0.01], [1,1,0.01]), wgsl`
  fn washer_hit(r: Ray) -> Hit {
    if r.d.z == 0.0 { return miss(); }
    let t = -r.o.z / r.d.z;
    if t < r.lo || t >= r.hi { return miss(); }
    let uv = r.o.xy + t * r.d.xy;
    let q = dot(uv, uv);
    if q < 0.25 || q > 1.0 { return miss(); }
    return hit(t, vec3f(0,0,1), uv);
  }
`, brass);
```

Change `0.25` to `0.0625` to halve the inner radius. The thin box gets fragments to the washer. Its thickness never contributes brass. The chart is in local length units and survives a camera move. At grazing incidence a coplanar ray has no isolated intersection under this definition. A bevel, thickness or a coplanar paint stroke would be a different piece of geometry that the author can write. The example deliberately exposes that convention in the first line of maths.

**3. Change how a light is estimated.** In a copy of the direct-light example, replace its entire many-light estimator with the following graph function. The imported vocabulary is the only prelude beyond WGSL built-ins. `toward` constructs a world segment with the surface's numerical origin offset. `world.beam` returns RGB ballistic transmittance to the endpoint, including opaque occlusion. `sun.E` is irradiance on a perpendicular plane. This recipe is for a Lambertian front face and one directional light. It needs no random draw, reservoir, old camera or history texture.

```ts
const direct = wgsl`
  fn direct(s: Surface, sun: Sun) -> vec3f {
    let c = max(dot(s.n, sun.wi), 0.0);
    if c == 0.0 { return vec3f(0); }
    return s.albedo * (c / pi) * sun.E
         * ${world.beam}(toward(s, sun.wi, sun.reach));
  }
`;
```

Here `s.n` is the unit face normal on this matte card. `world` is the scene query value captured by the example's TS function. `sun.reach` takes the ray outside the bounded occluding scene. To close only the woodblock shadow, bind the hole in this expression to `printWorld.beam`, where `printWorld` is the same object list with the washer replaced by a solid disk with the same transform. The camera, mirror and picker keep their original `world`. The source and expanded read set will identify the deliberate disagreement. A copy with an emissive area lamp can instead choose a point, account for its density and shorten the ray to that point.

**4. Write a medium.** In a shot with known units, replace the example fog's extinction integral by Beer attenuation for a homogeneous absorbing dye. Here `a` and `b` are distances measured along the unit world ray inside the clipped dye region. `absorber` pairs the law with that region and zero emitted or scattered light. A red particle in the dye, a camera ray and a sample on a lamp all consume this same function. The coefficients are in inverse metres. They have a large visible consequence over a metre and cost three scalar exponentials before specialization.

```ts
const dye = absorber(tank, wgsl`
  fn transmit(r: Ray, a: f32, b: f32) -> vec3f {
    return exp(-vec3f(0.2, 0.7, 1.4) * (b - a));
  }
`);
```

**5. Own the whole frame.** This complete module is an alternative inspection engine. A user can substitute it for `studio`. It uses the same washer exported above. It requests exactly one colour pass and paints outward normals against a calibrated grey background. `screen` supplies the vertex triangle, target and pixel entry. `pinhole` generates the world ray at the sample centre, with a graph-visible camera and film size supplied by the view. `nearest` links the consumer's own geometry and returns a world-space interaction. There is no compulsory material evaluation, environment, post chain or readback. The whole engine can be copied into another application.

```ts
import { screen, wgsl, nearest, pinhole } from "loft/render";
import { washer } from "./washer";
const find = nearest([washer]);
export default [screen(wgsl`
  fn pixel(xy: vec2f) -> vec4f {
    let h = ${find}(${pinhole}(xy));
    if !h.found { return vec4f(0.18, 0.18, 0.18, 1); }
    return vec4f(0.5 * h.ng + 0.5, 1);
  }
`)];
```

## The stable contract ends at executable work

A GPU needs resources of known shape, programs with compatible bindings, and commands in a legal order. A pixel needs considerably more meaning than that. Keep the former vocabulary in the runtime. Give the latter to whoever wrote the engines that produced the pixel. There is one recorded graph, including typed calls, loops, data references, raw WGSL with declared signatures, and source spans. Graph functions may run in a kernel or in a draw. The compiler specializes a *use* in a stage, folds constants, prunes dead fields, lays out resources, validates the module and emits a bundle. A reader can load that bundle with no compiler installed. The same bundle can feed a headless renderer or draw into an application's encoder. These boundaries already have real Rust crates. [Graph](../../../rust/crates/loft-ir/src/graph.rs) · [Bundle](../../../rust/crates/loft-ir/src/bundle.rs) · [GPU host](../../../rust/crates/loft-gpu/src/lib.rs)

Keep `Graph`, `Resource`, `Kernel`, `Pass`, `Bundle`, `Identity`, the error and verdict vocabulary. Extend a graph function's value types just far enough to express unsigned IDs and named product results. At the source level a sum such as `Miss | Hit(record)` is checked exhaustively. A stage can lower the sum to a boolean and the demanded fields. Today the wire's numeric types stop at floats, float vectors and bool. Assigning an integer ID to an f32 attribute would already merge neighbours above 2²⁴. A u32 lane and typed product flattening buy an actual capability. No wire tag for washer, quadric, reservoir, woodblock or phase function is needed. Those are functions and data. Only new execution capabilities, such as an indexed indirect draw or an acceleration-structure resource on a supporting backend, warrant an execution tag. Each such sum has one exhaustive dispatcher with a small handler for each variant.

The proposed bottom of the pass format describes an ordered render, compute or copy command with explicit resource views and access. A render command names entry points, vertex/index inputs or generated vertices, draw range, attachments, load/store and raster state. Compute names an entry and dispatch extent. Copies name subresources and byte or texel ranges. Chains of these commands currently implicit in the host become ordinary emitted lists. An encoder validates usage, alignment, aliasing, sample counts and the external attachment contract, then executes that order. The artistic decision to take a scene-colour snapshot for refraction moves into the recipe. The host remains responsible for implementing a valid snapshot on this device. A caller with a read-prohibited colour attachment can supply a sampleable intermediate or receive an error at the consuming pass. It never pays for an unrequested copy.

The orchestration library builds this list from resource versions. A writer produces a new version, readers specify which version they consume, and history reads explicitly refer to the previous frame and its initialization. An ordinary topological order works within one frame. Ties follow declaration order unless the author supplies an order. Temporal feedback is a pair of resources and a swap after successful submission. Independent passes can alias scratch storage after their last reads. Blending, depth tests, storage writes, atomics, implicit derivatives and visible intermediate targets constrain legal reordering and fusion. Specifying load/store and access on raw passes makes those constraints enforceable. An opaque side effect with insufficient declarations is an error at the pass. Two equal-size textures carrying different views or sample times require an explicit conversion in the render library. The executor knows only their formats and allowed accesses.

Aiming for hundreds of lines makes sense for the ordered-command interpreter alone. Graph analysis, wire validation, adapters, pipeline caching and error maps all have real costs. Score their sizes separately, including the source moved to the public library. A reduction in core lines bought by a private helper crate that still decides when fog veils a particle fails the design. The simple ownership test is to implement a third integration law in an external package against a released compiler. The compiler should see an old function signature and new maths. ## Render supplies the meaning of a hit

A render description is a collection of local geometries, material functions and placed instances. A surface geometry supplies a local conservative bound over a stated time domain, a function for intersecting one clipped ray, and a way to evaluate its surface attributes from a hit. An infinite plane may declare an unbounded domain and use direct evaluation. Raster meshes can supply triangle intersection from library code over exactly the imported indices and positions, and native raster coverage over those same triangles. A camera-only painted matte can declare that its only product is screen colour. An engine that asks the matte for reflection geometry gets a typed missing operation with the object and requesting integrator's source spans. The artist can give it actual geometry, compose it as a post effect, or explicitly omit it from that query's world.

The following are library contracts. Names in angle brackets describe statically linked types. They do not imply a GPU vtable or a per-pixel tagged union over every material in the library.

| Value or operation | What its caller can rely on |
|---|---|
| World ray | Origin in metres, unit direction, half-open distance interval `[lo,hi)`, time in seconds. A sample may also carry lens position, direction differentials or a cone footprint when demanded. |
| Local intersection | Object-space ray, same parameter as the world ray, possibly non-unit direction after inverse transform. Returns miss or first accepted boundary with `t`, outward geometric normal and the geometry's chart. Roots on the far endpoint are excluded. |
| Surface interaction | Stable instance and primitive keys, world position and geometric normal, front/back side and chart sufficient to reconstruct attributes at that time. Shading normal, derivatives and material fields are requested by users of the interaction. |
| `nearest(objects)` | Links an acceleration search and geometry functions into a function of the world ray. A tie in a query uses a declared stable key. Each ray class can bind a different world expression. |
| Segment transport | The beam function returns linear RGB unscattered throughput along a finite straight segment. A medium can additionally compute radiance integrated toward its start or sample a scattering event. Units, domain and directional conventions travel with those functions. |
| Material | Surface emission and BSDF evaluation, and where requested a direction sampler with density or discrete probability. The BSDF reads the same chart and time under raster, analytic and secondary hits. |

For placement, transform the ray by the inverse affine map, preserving the magnitude of the transformed direction. For a sphere quadratic this means retaining its `dot(d,d)` coefficient. The solved parameter then remains in world metres even under nonuniform scale. Transform the normal by the inverse transpose, normalize, and apply the chosen orientation convention for reflected coordinate systems. The geometric normal determines front/back, origin offsets and medium boundaries. The shading normal can carry woven cloth or hammered brass detail. An integrator needing the energy correction for a perturbed shading frame can read both. For raster hits, use perspective-correct interpolants or recover the triangle point from its coordinates. At coplanar ties an exact interchange with the ray path additionally needs matching raster edge and depth ownership. A candidate that lacks that relation cannot be silently substituted at a tied pixel.

The default view maps camera coordinates to WebGPU clip depth in [0,1], derives depth from the actual hit and uses one projection for raster and analytic draws. The camera looks through a named view and film sample, with the existing look camera's up convention. Host matrices carry the depth range, test and clear convention with them. A game with reversed depth supplies its matching mapping. Reconstructing distance from its stored depth needs the inverse projection, lens sample and extent. Linear ray distance, device depth and view-axis distance are distinct quantities with separate conversion functions. A visibility cache also needs time and the actual ray through the aperture for motion blur and depth of field. The default picker reuses the displayed sample or declares a centre-lens, centre-time query. Either policy is readable in its two call sites. Unjittered picking can be quite desirable in a game.

Inside `nearest`, a traversal recipe takes a bound and invokes the object's narrow intersection. One example searches a small linear list, another walks a stack over a refitted BVH, another walks cells of a repeated field. `beam` can compile the same surface rule to any-hit for opaque objects. For alpha-masked leaves the cutout in chart coordinates is part of accepted coverage, including its footprint convention. It must run before an any-hit early exit. If a cutout rejects a front root, resume at the next candidate, including later roots of that same primitive. The caller can supply the acceptance predicate to the leaf so this continuation gets compiled into the local root loop. A fixed footprint shared with a point shadow ray is an artistic choice, so identify the footprint used. Thin absorption multiplies throughput. Thick refractive glass bends a path and changes medium at a boundary. Its ordinary shadow ray can report blocked straight-through transport or use an explicitly chosen approximation. Caustics require sampling paths which reach the receiver through that glass. Colouring a straight shadow green cannot establish that a caustic is correct.

Use the smallest interaction at the particular observer. An any-hit sun ray through opaque brass needs existence alone. A click needs identity and depth. A brushed-metal reflection needs a tangent frame and a shading law. These are projections of the same geometry and acceptance code. The source returns enough to construct them, and the compiler computes backwards from fields actually read. An author can replace the search itself, including its stop condition, by calling the same local functions directly. The common interface ends at the answer a particular engine requires. Nobody has to return UVs for a fireball or a surface normal for a fog interval.

## Light supplies the meaning of a path

Light needs answers to three different questions. What happens at this surface? What reaches it from elsewhere? How shall we sample that integral this frame? A material gives emission and scattering in a specified frame. A world gives intersections, participating regions and emitter geometry. An estimator consumes those answers and returns radiance. A sun recipe can be as short as case 3. A many-light estimator takes a sample from an authored proposal, asks for visibility, and weights the contribution by the sampling probability. A light can be sampled by area or solid angle. Changing measures requires the distance-squared and emitter-cosine Jacobian. A point light carries discrete mass. A direction sampler specifies the event it returned, its measure, and its weight, including the selection probability of a lobe. Delta reflection cannot be fed to a continuous-density MIS formula by assigning it an arbitrary large PDF. This distinction buys the caller the ability to compose samplers without silently changing brightness.

For media, the useful result on a segment is the pair `(L,T)`. `L` is radiance arriving at the segment start from sources inside it, including in-scattering estimated under the chosen incident illumination. `T` is transmittance to the far end. For two contiguous pieces in near-to-far order, composition is `(L₁ + T₁ L₂, T₁ T₂)` componentwise. A surface or emissive particle at the far end contributes `T * Lsurface`. An absorbing slab one metre deep in case 4 gives `(0.81873, 0.49659, 0.24660)` to five decimal places. Splitting it at any interior point must give the same throughput within f32 tolerance. For overlapping scattering media, gather all active coefficients on each interval and integrate their summed extinction and source there. Applying two complete fog layers consecutively generally gives the wrong in-scattered light. Independent optical depths add for pure attenuation. A Gaussian density integral, a grid lookup and a user's dye can therefore share a shadow beam even when they require different estimators for radiance.

Particle placement reads pose or simulation buffers at the declared time. A spark can be a finite emissive surface, a volume with a density profile, or a screen-space accent in the final pass. The first two participate according to the physical law their author supplied. A screen-space accent can use depth for artistic occlusion. The library cannot infer its extinction from a blend flag. Similarly, an artistic transparency alpha may describe partial coverage, stochastic leaf coverage, or a compositing weight. The sample engine makes that decision once when it constructs the object and uses the resulting law wherever coverage matters. This removes the port's current inference from `depth_write` to veiling while retaining the good picture it originally served.

**Three engines to ship in source.** The studio engine uses instanced raster for triangle primaries, proxy raster plus local intersection for small analytic objects, and bounded field search for a folded object. A public direct sampler handles the sun and emissive meshes, a BSDF sample handles a glossy secondary ray, and a volume segment clips at the actual surface. Materials, sky and emitters have linear working values. A final film function chooses exposure, tone mapping, grain, grading and exactly one display transfer. Bloom reads scene-linear highlights before that transfer. Lens and shutter samples belong at ray generation or their explicitly approximate post substitutes. A user changing highlight roll-off can keep the entire geometry and transport assembly.

The reference engine generates a lens/time sample, intersects, samples the active medium up to that boundary, adds emission and direct light, samples a continuation, updates throughput and repeats. Explicit Russian roulette with survival compensation makes arbitrarily long paths possible. A hard bounce cap defines a different reference. The engine needs sampling support wherever the integrand contributes and a sampling strategy suitable for the paths being compared. For instance, a caustic lit by a point source through ideal specular events can require a light-side strategy. Ship a small independent analytic oracle for such scenes before claiming convergence. A readable first implementation can run a complete path in one compute invocation. A copied version may enqueue hit/material/shadow work for wavefront execution. Both receive an explicit sample key `(pixel, sample, bounce, dimension)` so queue order cannot change which random variable a path draws. Store linear sums and counts before any denoising or tone mapping. GPU queue scheduling and transport are separate pieces of source that can be changed independently. [PBRT's GPU integrator](https://pbr-book.org/4ed/Wavefront_Rendering_on_GPUs)

The woodblock engine starts from the same positions, geometric normals, material chart and light queries. Its illustrator chooses the signed width of a hatch in chart space, selects one or two hard shadows for the print, and cuts contours from depth and object identity. A demoscene variant copies the inspection engine in case 5, replaces `find` with a bounded fold, and computes ink and atmosphere inside that single screen pass. If the author later wants to place a boat in their ocean, export the ocean hit and segment functions before composing the final colour. The boat and ocean can then share depth or query one another through arbitrary cameras. There is no registration step for any of these engines. Each exports the same thing an application can construct directly, an executable pass composition with declared inputs and outputs.

Build material capability outward from the quantities these engines can check. A reciprocal microfacet conductor needs an energy budget for interreflection between facets. The existing single-scatter GGX lobe at maximum roughness, normal incidence and unit Fresnel integrates to `1 − ln 2 ≈ 0.30685`. A unit-reflectance opaque white conductor in a uniform furnace should eventually return unit radiance at equilibrium. A new multiple-scattering term must recover the missing energy at roughness one while maintaining the polished highlight at low roughness. Compare each isolated lobe by angular quadrature and the complete swatch to a separate random-walk reference. The earlier white dielectric furnace passed even with this conductor deficit. Add anisotropy, layered clearcoat, sheen, subsurface transport and thin film as inspectable functions with their own targets. Subsurface light may enter and leave at different surface positions. That example extends the sampling program to a spatial event and queries object membership. Squeezing it into a local colour multiplier would lose the capability. For film interference, specify the sampled wavelengths or the RGB approximation and test at oblique angles. [Measured Loft furnace and lobe](../../2026-11-18_pbr_style/NOTE.md)

## What Loft has to invent

The hard new work is deciding **when two implementations may stand in for one another at a particular observation**, then compiling only the answer that observer buys. A mesh and its BVH share the same indexed triangles. A folded object and a list of copies can share a part equation yet differ on a mirror plane, on which copy owns a point, or on the material chart there. A substitution legal for binary shadows may be wrong for an ID image. One legal for camera rays may fail for rays starting inside a solid. Traditional pass inputs such as a depth texture do not state those conditions. A generic shader interface by itself establishes types alone. Loft needs an executable account of this relation, short enough that the author of a new shape can use it without learning a proof language.

Start with the easy relation. There is one function for the accepted hit. Generate the existence query by projecting the hit to a bit, preserving all dependencies of acceptance. Generate a pick by projecting to key and distance. Both inherit their meaning by construction. A proxy box must conservatively contain every accepted point. A finite geometrical constructor can derive that box. Interval analysis over declared parameter and shutter ranges may certify a user function. If a bound is a mere author assertion, print its origin and offer an unculled direct search to the engine. A raw shader may run on the GPU and carry an independently measured bound. That gives a measured result over the tested inputs. Requesting a CPU proof for that shader gives `Unproved` or the existing named unsupported/undecided reason. Never manufacture a second implementation just to claim a twin.

Next, let a public geometric rewrite construct an alternative with an explanation the compiler can verify. For a finite fold, generate each instance transform **and the half-space tests induced by successive fold decisions**, carry the original cell key through the inverse chart transform, and tie-break points on a mirror plane by the original branch rule. List leaves conservatively intersecting the queried region and intersect local geometry within their clipped ray spans. When the folded function asks only for zero-set hits on piecewise isometric hard unions, this gives a candidate for the same observer. A cell boundary that is itself a visible surface requires its own intersection according to the original definition. A smooth blend across cells, a non-isometric warp, or an unresolved ray exactly on a fold plane can violate the derivation. Reduce the eligible domain, retain the original evaluator there, or leave the rewrite unproved. For field shading, matching the zero set alone does not establish a matching gradient or chart. Carry those obligations only into sites that read those properties. The measured 172 mismatched pixels in the tree make an excellent counterexample to a too-generous equivalence rule. [Folded tree and coral](../../../docs/tracing_sota.md)

Implement these first as library derivations for specific constructors, with a small Rust checker for structural identities and conservative inequalities using the existing interval machinery. Store where an obligation arose, its domain, required outputs, numerical convention and verdict. A finite probe bank can falsify a derivation or support an artist's error budget. It cannot certify arbitrary raw WGSL. An automatic exact choice requires a checked construction and the declared numerical tolerance, including visibility discontinuities. A user can explicitly select a measured substitute or write an engine with wholly different semantics, as the solid print shadow does. Both are normal routes to executable GPU work. When a check is inconclusive, an available canonical implementation can be selected by name, with its cost, or the query can refuse if the author required a certified accelerated route. No unchecked alternative earns the label exact.

Finally retain an explanation at the observer after linking. For one chosen pixel or supplied world ray, rerun a debug specialization which writes ordered candidates, clipped spans, accepted key, geometry and material source sites, transmittance factors and sample densities to a bounded buffer. Overflow returns a visibly truncated trace and count. It need not slow production frames. A composited pixel can point back to its pass and resource versions. A procedural hit inside a folded cell can point back to the original fold clause after inlining. The graph also lets `loft show` print the chosen search, discarded alternatives, GPU code and cost inputs, and `loft context` generate callable signatures from the same records. A validation error inside a WGSL hole maps to the defining source span and the instantiating observer. The useful artifact after a bad shadow is the accepted blocker and the exact line that admitted it.

We inherit CSG interval arithmetic, analytic intersections, sphere tracing, gradients, tile lists, BVHs, raster visibility buffers and frame graphs. We inherit BSDF sampling, MIS, wavefront queues, reservoirs and history rejection. Late shader specialization also has a substantial precedent. The research claim here concerns their combination with consumer-authored equivalence at the observer, projected code generation, and a public choice of schedule under one picture identity. Step 1's surveyed systems supply pieces of it. We have no grounds for a claim of historical priority for every component. Our proposed contribution becomes meaningful if a consumer supplies a new geometry once, earns a faster certified path for one query class on one adapter, and can inspect and replace that decision with no compiler fork. If whole-frame speed or the human rewrite test misses, a large library of examples alone does not establish state of the art. ## What a run should cost

At each use, enumerate only candidates with the required semantics and features. Estimate setup plus steady work over the expected lifetime of data. For example, cost a software hierarchy as `build + updates + rays × (visited nodes × node cost + tested leaves × test cost)`. Primary proxy raster instead costs covered samples including overdraw, submitted instances, depth traffic and winning shading. For a field, count steps, distance terms per step, normal evaluations and shadow steps separately. Check for a conservative local list even when steps originate outside a cell. Use a grid, branch hierarchy or the generator's inverse cell map for many instances. Marching an N-way minimum at every step has no place as the scalable default. Triangle raster wins outright for many imported meshes, and analytic vertex evaluation of a swept surface wins if the authored geometry is that sampled surface. A tessellation of an ideal curved surface carries a chord error and needs its own accuracy contract.

A practical selector starts with two candidates at a hot site, compares their **full compositions** in alternating warmed rounds, and stores the result tied to adapter, driver, shader, observer, scene domain and resolution. Correlated decisions matter. Moving a single surface from raster into an already required reflection BVH can be cheap. Introducing that BVH for the first time charges the build to the choice. Similarly two locally optimal shaders can create a slower frame if their outputs force a resolve. Record the selected schedule in the build or frame identity, seed any calibration deterministically, freeze it for scored runs, and expose the selector's source. Recalibration is earned by a changed dependency. No per-object benchmarking loop belongs on the loading path. When history affects the image, the identity must include initial state or checkpoint, resets, sample sequence and prior inputs. A hash of the current camera cannot reproduce yesterday's reservoir. [Existing identity fields](../../../rust/crates/loft-ir/src/identity.rs)
