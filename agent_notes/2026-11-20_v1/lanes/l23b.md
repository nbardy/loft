# Phase 3 motion core

## Predictions before building

A fixed 120 Hz tick with absolute time and sequential disjoint writes should give zero differing bits at all 481 ticks, including the six-tick render stall. The 20 mm fixture should produce a Missed verdict at the existing 0.05 mm threshold. The outbox fixture should preserve two 32-byte events, and the integer pixel-centre oracle should cover 9,664 and 12,080 samples.

## What landed

Scheduled row-local operations emit one bounded `advance` entry per kind. The entry applies disjoint writes in schedule order, publishes full packed state and writes one frozen 32-byte `VerdictRecord` per check and row. State layout hashes follow all columns. The runner splits spans at the 64-tick limit and at retained ticks, indexing checkpoint copies by absolute tick. Equal-layout bundle swaps preserve state and checkpoint history.

The CPU twin interprets the same validated Naga entry and explicit f32 FMA operations. Native `step_pass_cpu` reads the last submitted storage bytes, applies the selected rows, then uploads results for subsequent GPU ticks. Raw operations outside its deterministic subset return `Unsupported`. The CPU method synchronously maps on native and returns `Unsupported` on WebGPU. The existing still sampler supports scalar float snapshots.

Law source uses `emit_event(Tag, instance_id, site_id, payload)`. The common WGSL writer and reflected storage binding also serve generic compute passes. Each outbox uses three staging slots with deferred maps. A slot becomes eligible two frames later. A busy slot returns a recoverable capacity error and overflow counts travel with their producing frame. Event tags are stable 32-bit symbol words exposed by `event_tag`.

`set_pick_source` publishes visibility, depth and the inverse matrix for a frame. Both pick methods issue the same sample-zero compute load and use the same decode and unprojection. The compute load supports multisampled depth. Asynchronous mapping stages 12 bytes in a 256-byte buffer. The runner methods return typed setup or readback errors through `Result`.

It selected `test(/^motion_(wave_)?cpu_/) | test(checkpoint_windows) | test(outbox_record_prefix) | test(picking_shader_and_unprojection)`. The l23c source snapshot was read from `out/l23b-peer` through `LOFT_MOTION_FIXTURES`. On the combined branch the tests use the merged scenes and prelude directly.

The first filter inadvertently included the older CLI `fake_foot_20mm` test, which initialized a GPU and ran its compute check. The reruns excluded it. The CPU verdict and scene mutant checks above independently produced the expected results. No GPU render or profile ran in this lane.

## Files

- `crates/loft-passes/src/{check,emit,fusion,lib,motion,program,sexp}.rs` contain type checking, emission, motion bundle construction and dispatch metadata.
- `crates/loft-runner/src/{encode,events,lib,pick,stepping}.rs` contain pass execution, checkpoints and the two readback paths.
- `crates/shared/{compute_twin,visibility_ids}.rs` contain the Naga evaluator and shared visibility record decode. They compile through runner modules with the existing crate graph.
- `crates/loft-cli/src/native/motion.rs` uses the runner advance entry for sampling. `crates/loft-cli/tests/motion_lane.rs` and `crates/loft-cli/tests/motion_lane/` contain the proofs and fixtures.

It covers alternating CPU/GPU ticks and ring restore, the Boss scene's impact and slip transition and the Washer async/sync IDs. The three GPU tests compiled. GPU measurements are pending.

Retain both lanes' changes in `loft-runner/src/encode.rs`. The l23a compute pass wrapper and parameter upload need to carry the fused-pass metadata, dispatch and outbox lifecycle from this lane. Route CPU stepping to l23a's current parameter shadow after combining the lanes. The production Boss source belongs to l23c. The test injects the two event calls into that source in memory, before the velocity update.
