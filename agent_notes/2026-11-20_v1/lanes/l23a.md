# L1 Interactive Edit

## Predictions

- The tape decodes all 56 frozen opcodes, refuses reserved words and a 33rd live value, and releases a dead source before reusing its register for a destination. The compute fixture validates on CPU.
- An edit burst starts only the last request after 400 ms. A pending result from the previous edit never becomes active.
- Two changed parameters produce one deferred upload. Setting the same encoded value produces none. Only a group referencing a newer table epoch is stale.
- The telemetry fixture counts 2 ALU, 1 transcendental, 1 storage load, 1 storage store, 64 workgroup bytes, 1 loop, 1 branch and 1 call. Five direct expansions of the synthetic BSDF body multiply its ALU count by five.

## Implementation

- Tier 0 decodes the frozen words, allocates 32 vec4 registers without spilling, validates loop pairs and runs the CPU tape. The precompiled WGSL entry uses one tape and one instruction PC stream per kind. A native worker promotes a ready Tier 1 shader after 400 ms of quiet. Edits invalidate queued and in-flight results by generation. Eight successful pipelines per instance are kept in LRU order.
- `loft show [--kind K] [--plan] [--json]` prints WGSL and author declaration and expression locations from the existing provenance map. `loft build SCENE --json PATH` collects telemetry directly from the compiled Naga modules. The .sexp build path also accepts `--json`. `loft profile --json PATH` includes module counts and per-frame, per-pass timestamp samples.
- Live parameters write a std430 shadow buffer using the existing group-0 layout. Multiple edits coalesce into one write before the next encode. Source reflection currently follows Phase 1.5's authored f32 slots. The Runner accepts all six types in the frozen ParamMeta.
- External resources use the same wgpu handles. Buffer validation checks capacity, binding minima and usages. Texture validation checks reflected view class, usage and format where WGSL specifies it. Allocation accepts a host descriptor and exports the resulting handle. For a host-bound texture, the first compatible handle establishes the resource's exact extent, format, sample count and mip count. Later replacements must match. Encoding rebuilds only bind groups that reference a changed table.

## Integrator handoff

- To use the precompiled tape in Runner, include `loft_passes::tier0::VM_WGSL` in a compute bundle. Use entry `loft_tier0_main` and bind its tape at group 1 slot 0 and the kind's row table at group 1 slot 2. The tape table starts with the word count followed by packed words. Register the pass with `register_tier0`, upload with `hot_swap_tape` and queue `hot_swap_module` with the specialized shader using the same entry and compatible pipeline layout. Encode polls promotion on native. Loop trip counts must be uniform within the dispatch bucket. The compute fixture assumes a single vec4 row per invocation. The standalone `loft_tier0(row_base)` can address wider records.
- Run the roughness and sun sweep and zero-copy buffer test on a Runner bundle. Preserve the attached device across host allocation and runner execution. Use one fixed dispatch with an external table, write the host buffer through the shared queue and read the output after the next frame. Sweep two ParamIds, measuring pipeline creation around load and both updates. A storage texture fixture can use `textureLoad` or `textureStore` without requiring a sampler object.
- The frozen TableDecl cannot declare descriptor-level texture dimensions or format for shader-sampled textures. Exact first-bind validation and allocation directly from bundle data need that contract. Frozen Bundle also carries no bake-dependency metadata. Phase 4 must connect its OnDirty scheduling to changes in parameter IDs.
- Phase 1.5's render executable uses its own Loaded path. Automatic E+ query-to-tape lowering and inserting the tape into its render and shade stages remain to be integrated. The native worker uses wgpu's synchronous API on another thread. The pinned Rust API exposes no browser async pipeline method, so browser promotion is a typed refusal. The Phase 5 bundle-build owner can reuse `loft_passes::telemetry::collect` while adding the .loftb output.

## Proof

- `CARGO_BUILD_JOBS=2 tools/dev.sh check loft-cli` passed on the first retry after correcting the wgpu buffer-limit width and the range evaluator borrow.
- `CARGO_BUILD_JOBS=2 tools/dev.sh test loft-passes -p loft-runner -E 'test(l23a_)'` passed 10/10 on the first run. The 56 CPU opcode fixtures scored within 1e-5. The E+ sphere CPU twin agreed at all four probe points. Naga validated the WGSL and its switch contained exactly IDs 0–55.
- The pipeline promotion state test passed at 399/400 ms and rejected a stale generation. Parameter clamping, deferred write count and per-binding epoch invalidation passed.
- The JSON telemetry fixture measured the predicted counts. The inline mutant measured 20 ALU and no calls against 4 ALU and one call in the original.
- GPU timing, buffer visibility and pixels are pending the integrator. Neither GPU rendering nor pipeline creation ran in this worktree.
