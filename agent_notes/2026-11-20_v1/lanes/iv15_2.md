## Reproduction

Use a separate checkout of incoming main at `78ef244` for the baseline. Copy the saved release CLI into that checkout so the timing collector resolves its original scene and stdlib paths. Run from a separate candidate checkout.

```sh
incoming="$HOME/git/_wt/loft-incoming-78ef244"
archive="$HOME/git/loft/out/meta/v15_exec"
mkdir -p "$incoming/out/meta/v15_exec/bin"
cp "$archive/bin/loft" "$incoming/out/meta/v15_exec/bin/loft"
CARGO_BUILD_JOBS=2 LOFT_GATE_PROFILE=release LOFT_TIMING_MARGIN=0 \
  LOFT_BASELINE_BIN="$incoming/out/meta/v15_exec/bin/loft" \
  LOFT_BASELINE_PICTURES="$archive/candidate-release-pictures" tools/check.sh full
tools/check.sh lines
uv run --script tools/corpus_tokens.py "$incoming" .
```

The full driver checks the workspace for wasm32 with the web-sys feature, runs workspace doctests, then builds all release bins, native test harnesses and examples in one invocation. The recorded driver overlaps the single CPU grammar scan with compilation and joins it before GPU execution. It runs each harness serially under the GPU lock. The sign interval for six independent AB/BA pairs has 96.875% coverage. A triangle p95 at or above 0.150 ms invalidates a timing window. The binary and the three structural/beauty planes used for the baseline came from the matching scored executable revision.
