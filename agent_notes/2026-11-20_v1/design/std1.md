# Standard library for Loft

## 0. Old stdlib audit

The old woodblock renderer could repaint a serpent, a shell and a field-traced solid without replacing their visibility algorithms. Keep that property. Put the ink calculation in an importable file, feed it light from the chosen integrator, and let the engine select visibility and post. Keep the pinned v1 pictures as the control for the move.

**Inventory method.** Sources below are from `legacy/2026-11-19` (`acb7e8b9`), read with `git show`. Sizes are physical lines including comments and blanks, and whole-file **o200k_base** tokens including the final newline. Reproduce any row from the repo root with the following command, changing the path. The 124 source rows cover 4 ports, 54 port-rewrites, 36 reference-only entries and 30 drops. File totals count declarations, comments and implementation together; a file’s size is not a block/call ratio. Main was inspected at `e32dfe2`.

```sh
git show legacy/2026-11-19:src/style/light.ts | uv run --with tiktoken==0.14.0 python -c 'import sys,tiktoken; s=sys.stdin.read(); print(len(s.splitlines()),len(tiktoken.get_encoding("o200k_base").encode_ordinary(s)))'
```

**Consumers.** Names identify example entry points or a stated transitive path through a recipe. “Sheet” means a deliberate restyle of `examples/{serpent,shell,serpent_scales}.ts` by `src/style/sheet.ts`. Those are real common-camera consumers of all seven styles, independent of their scene defaults. “Slice” and “Furnace” refer to the ordered renderer in `examples/slice/`. Its row/material ABI differs from the paint-expression renderer used by the bosses. “Crab Live” means `examples/motion/crab_live.ts` and its `stage.ts` consumer of the posed buffer. An optional path is identified as such.

**Cost instrument.** Milliseconds below are historical measurements. Counts of taps, loops, reads, passes and complexity are source estimates. They apply at the stated stage. The 1280×800 Bruiser comparisons had GPU contention and changes below ~0.3 ms were unresolved. The volume, precision and DoF figures are M4 results. These workloads do not predict v1 p95 by addition. [Measured style comparisons](../../../docs/legacy/styles.md) · [PBR against toon](../../2026-11-18_pbr_style/NOTE.md) · [Print lighting profiles](../../../docs/legacy/lighting.md) · [Coral tracing](../../../docs/legacy/tracing_sota.md) · [Motion measurements](../../../docs/legacy/handoff/2026-11-19_motion_chief_scientist.md) · [AO and sky](../../2026-11-18_cook/pbrsky.final.md) · [Volume](../../2026-11-18_cook/volume.final.md) · [Precision](../../2026-11-18_cook/f16.final.md) · [DoF and grain](../../2026-11-18_cook/dof.final.md)

**Decisions.** Each row has one verdict. A port retains the algorithm and rewrites its representation in E+. A port-rewrite identifies the part to keep and the change needed. A reference-only row has a tagged source pointer in the [reference index](../../../stdlib/REFERENCE.md). “Drop” retires the legacy implementation.

## 1. The stdlib/ tree

A scene author chooses a named engine, for example `use stdlib::engines::woodblock_realtime`. An engine author chooses one schedule, one transport estimator, one style and a sequence of post passes. A material author writes `material(p,n) = ggx(tint, rough, metal)` in the kind. Neither changing the ink nor changing the transport requires editing that kind. The legacy sheet is the precedent for the first swap. Applying the same primary-hit ink function to a converged path estimate is the proposed extension.

**Import direction.** Core is the root. Math, frames, SDF and noise depend only on core or a lower mathematical primitive. Geometry uses them, including the frame scan for sweep. Materials use math and the energy table. The world payloads precede lighting and transport. Sky uses noise/math. Lighting may call sky, and motion may call frames and geometry. Shared print parts use those lower files. A surface style imports print parts, lighting and noise as needed. For example woodblock uses noise/value and lighting/print. Integrators call material/world/light queries. They return incident-light and physical radiance estimates to the chosen style. Post consumes completed images; it may sample noise. Schedules declare *where* callbacks run and carry typed parameters supplied by the engine. They have no imports of concrete styles or estimators. Engines are the top of the graph. A dependency cycle is a build error.

The transport/style boundary is a value boundary. Below are proposed E+ declarations. `anchor` is the hit in the kind’s local coordinates, so ink remains attached to a moving surface. `footprint` is local metres per pixel along its two principal directions. The visibility path supplies it from projected geometry, explicit ray differentials or neighboring primary rays. Derivatives of a divergent compute invocation cannot supply it. The kind provides pigment via its material evaluation. Existing BSDF-only scenes use their existing evaluated pigment convention in the parity recipe. New styles can bind authored pigment/emission explicitly.

```loft
struct Surface {
  p: p3@World, anchor: p3@Local, n: n3@World, view: d3@World,
  uv: v2, footprint: v2, pigment: rgb, rough: f, kind_id: u, row_id: u
}
struct Lighting {
  key: d3@World, key_visibility: f, ao: f,
  direct: rgb, indirect_diffuse: rgb, indirect_gloss: rgb, emitted: rgb
}
```

`Lighting` stores linear outgoing radiance by contribution, plus the key direction and visibility used by graphic styles. The engine binds one explicit world (and optional distinct shadow world) when linking estimator queries. Primary kind and row IDs identify surfaces for reuse, material reconstruction and coverage. The direct estimator evaluates the BSDF at the light, multiplies visibility once and carries the result. ReSTIR changes selection/PDF weights. The reference counts emission and direct at the primary hit and classifies continued paths by the first scattering lobe. A mixed-lobe estimator either accumulates per-lobe weights at that event or samples a lobe with its selection probability in the weight. Sum must equal the original path estimate. For PBR, finite-visibility AO can modulate approximate environment lighting; a traced indirect estimate arrives with AO=1. A black emitter remains black. Per-emitter nonlinear scattering belongs in a material lobe evaluated at each sampled direction. A graphic band over total illumination belongs in the final shade function. Those operations do not commute. A miss shades the selected sky. An unresolved trace retains its truth status. For reference pictures, average linear components for each primary surface/coverage sample **before** applying a nonlinear ink band, then resolve coverage and finish. Averaging quantized noisy samples produces different bands. Preserve material/coverage IDs at silhouettes. The woodblock reference is a stylized presentation of a physical estimate.

## 2. Module mechanics

1. **Resolve a file.** The nearest workspace ancestor holding Cargo.toml and stdlib/ supplies the std root. `use stdlib::styles::woodblock` resolves exactly `<root>/stdlib/styles/woodblock.loft`. A local `use self::ink::woodblock` resolves exactly `ink/woodblock.loft` beside the **importing file**, including inside nested forks. No directory scan, fallback filename or implicit folder module. Diagnose missing files at the use span. The resolver receives a source provider so native, editor, tests and bundle builder see the same graph. Bundles replay the linked result without a filesystem search.
2. **Scope a name.** Bare `use P` binds its last segment as a module name; `use P as ink` binds only `ink`. `ink::shade` names a public declaration. `use P::{name}` and `use P::*` introduce public names into that file only. Imports do not re-export names. Private helpers and constants are lexical to their file. Public kinds, spaces, types, functions, lobes, laws and schedules have stable identities (canonical module, local declaration). The global ABI’s World/Local conventions and space namespace remain supported. Report collisions with both spans, unresolved/private names, unsupported import targets and full cycle chains. Never take the last import on collision. Two modules may export `shade` simultaneously.
3. **Load only what is used.** Auto-load core.loft once. Traverse imports in deterministic source order, intern canonical file IDs, coalesce a diamond and reject a cycle using the active stack. Keep source-file/span mappings and explicit build/row/pass order stable. A library file declares kinds, functions, schedules and build functions. It cannot inject scene build effects just by being reached transitively. The root scene’s explicit build runs once. A direct `use` of an engine exporting one entry schedule selects it when the scene omits a complete schedule. Two candidates are ambiguous. An explicit scene schedule can consume imported declarations without activating their schedules. An omitted schedule with no selection uses the *named* default Realtime recipe as a dependency. This preserves existing scenes with no camera/engine declaration. No compiler list of legal engine names.
4. **Migrate all entry points.** Main’s CLI sorts 16 top-level lib paths (607 lines including Act/Roam aliases). Parser item Use currently discards the wildcard. Prog::index checks an allowlist. defaults.rs selects include_str! recipes, including for the spectral study. The phase5 corpus runner, tests, demos, tools and raw WGSL source emitters also assume paths or global symbols. Pass an explicit module graph to all clients. Resolve `loft_user_…` references and implicit shader helper dependencies by declaration ID before mangling, including spectral, reservoirs, BSDF/energy, paper and sky. Assign stable IDs for row ordering at link time, independent of import sorting or cache hits. Keep both migration files under stdlib/migration. The bead observation harness supplies its existing scene-local `observe(uv:v2,extent:v2,seconds:f)->v4` entry. It calls `observe_bead(bead_fragment(uv,extent),bead_ink())`; the library’s observer takes data and has no reverse import of a scene. Preserve the frozen observer’s output byte for byte. Keep diagnostic paths/source identity for moved files. Route old supported `std::…::*` and `engines::…` spellings for external callers through a finite documented migration mapping in the loader; convert all tracked callers and audit actual exported symbols, including intrinsic quant operations. No physical duplicate source or symlink prelude.
5. **Fork by explicit binding.** Copy a file, keep its internal `stdlib::…` imports, edit it, select it at the file that owns the binding. Importing a second woodblock at the scene root cannot change a library engine’s lexical choice. Copy that engine too if its import needs to change. There is no registry, directory-priority shadowing or installed-package mutation. Diagnostics should link to the copy on errors in it.

Current evidence and grammar are in [CLI source loading](../../../crates/loft-cli/src/main.rs), [default schedules](../../../crates/loft-passes/src/defaults.rs), [the parser](../../../crates/loft-parse/src/parser.rs), [corpus runner](../../../crates/loft-cli/examples/phase5_corpus.rs) and [the spectral import](../../../scenes/spectral_caustic_study.loft). An engine file on disk alone does not establish that main supports arbitrary imports or higher-order schedules.

## 5. Precompilation with stdaot1

Use the same module graph for fresh compilation and deserialization. Cache parsed/checked **module IR** with symbolic references and stable local IDs. Link the reachable declarations, resolve scene-dependent kinds, Radiance, generic spaces, callback selections, raw WGSL bindings, asset layouts and row offsets, then lower/fuse at the final program boundary. Deferred space inference or a world query with a scene-specific implementation stays parametric in the artifact. Keep concrete instantiations in a separate cache when worthwhile. Caching a final shader that embeds the first scene’s row IDs would misrender the second scene.

A module key hashes its bytes, compiler and std ABI/cache schema, language/features/target assumptions that affect checking, and the ordered import names/aliases and dependency keys. Use a content DAG, including core and any raw shader/bake sources, with path-independent bytes for portable identical sources. Bind canonical module identity and span provenance separately when reusing blobs; identical copied source at two lexical paths must resolve its own relative imports and retain its own nominal type identity. A generated artifact that embeds a path or resolved identity must include it in the corresponding link key. Store e.g. `target/loft-cache/std-<hash>.bin`. Coalesce identical in-flight compilations, validate schema/length/hash, and publish atomically after success. Report cold, dependency change, compiler/schema change and corrupt artifact as distinct reasons in `loft build --json`; corrupted bytes are never accepted as a hit.
