## How Keel works

- **Forks and worktrees.** On Keel main, `keel/scripts/lane.sh new NAME BRANCH` forks the invoking checkout’s committed `HEAD` with an explicit base and `git cambium add -ephemeral`. Names default under `~/git/lanes/room-runners`. It locally populates the pinned `keel/crates/kit` gitlink, propagates the kit’s known remote refs, and uses its registry-only seed only when Cambium leaves the target empty. `lane.sh done` checks path containment, cleanliness and unpublished kit commits before retiring the lane. Git refs and config are shared. A past `git submodule deinit` affected every workspace. The direct-Cambium branch puts root, merge target, pruning and `submodules = true` in `.cambium.toml` and removes the wrapper and fallback seed. [Current launcher](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/scripts/lane.sh), [Direct config](https://github.com/nbardy/room-runners-arena-lib/blob/889204e138fc51f0560ffad89ae742c9d42f2bff/.cambium.toml)
- **Cache boundary.** Each lane owns writable `keel/target` and `keel/lab/target`. Cambium clones third-party outputs keyed by each lock and the Rust toolchain. Local freshness records, binaries, incremental state and evidence stay out of the seed. A whole-target clone previously told Cargo that local units were fresh while the binary still used the original checkout’s `CARGO_MANIFEST_DIR` for shader reload. `cache-env.sh` admits lane-local targets, uses sccache with a 6 GB default and incremental off, and sets the native `keel_hack` cfg. A compiler invocation with different flags misses seeded hashes. Keel scored 0 of 249 third-party recompiles, 56 local rebuilds in 66 s and 0.26 GiB new disk for a 7.4 GiB logical target. The initial probe with mismatched flags rebuilt 239 third-party crates. [Target policy and measurements](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/.cambium.toml), [Cache environment](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/scripts/cache-env.sh)
- **Compile and gates.** `keel/scripts/dev.sh check|lint|test|build|run CRATE` uses pinned Rust 1.99.1, `--locked` and shared gate flags. A light, niced compile can run beside the one heavy compile, and long executable runs start outside the compile lock. `--fast` uses the optimized `lab` profile with 16 codegen units and LTO off. `dev.sh plan --proof` prints the evidence commands for the diff. `check.sh static` buffers parallel source checks, including dependency boundaries, fmt, script types, dependency hygiene and gate self-tests. `quick` selects changed crates and reverse dependencies or gives the reason for a full gate. `full` runs Clippy, nextest, doctests, the kit and browser/worker checks. The lab has its own lock and gate; game API edits can select lab Clippy without selecting its tests. [Edit loop](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/DEV_LOOP.md), [Gate](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/scripts/check.sh)
- **CI.** The Ubuntu PR and main job installs the pinned toolchain, matching wasm-bindgen, Hakari, nextest and cargo-machete, uses Rust cache and a frozen pnpm install, and runs the Rust gate. It builds the locked native server and WASM client, serves them as a pair and runs Chromium `screenshots,reconnect,latency,lifecycle`. It uploads the browser report and server log even on failure, plus the build products on success. There is a separate source-controlled `objective-lamp` audit scene for staged art verification. The CI checkout currently omits `submodules: recursive` even though the static gate explicitly requires the kit. A fresh-runner reproduction should check that gap before treating the workflow as a known-green template. [CI workflow](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/.github/workflows/ci.yml), [Lamp audit scene](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/content/audit/objective-lamp.json)

## Practices Loft can adopt

Its legacy Rust workspace already has sharded static checks, an integration-test layout check and the nextest policies below. Apply the gaps to the root Rust workspace that will survive the port. ## The render splice

Keel’s native preview and browser turn published room state into `game_client` frame output. Tidewar’s `present::bships_geometry_frame` composes a CPU `Scene3D` with shared static triangles and per-frame dynamic art. `objective_overlay::lamp` reads the projected `Game::Lamp` at the interpolated render tick, classifies `LampLook` through `boss_art::lamp_look`, and calls the GPU-free art crate. Keel rasterizes opaque hulls, terrain, procedural canopy and sea, alpha effects, sprites and UI on its device. The offscreen gallery already drives the room wire and client clock and uses `Renderer::new_offscreen` to capture through the normal renderer. [Tidewar presentation](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/games/game_client/src/present.rs), [Lamp adapter](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/games/game_client/src/objective_overlay.rs#L314), [Gallery fixtures](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/tools/keel_gallery/src/fixture.rs)

Attach once from the existing Keel device and queue, in a native render-side adapter behind a default-off feature. The frame splice is inside `MeshPass::render_timed`, reached through `Renderer::render_composed`. When the Lamp row is active, close the opaque 3D pass, encode Loft on the same encoder and the selected scene color/depth views, then resume Keel alpha with `Load`/`Store`. Use the current ping-pong history views before `Temporal::present` when active. Non-temporal native first light uses the offscreen base-format `Rgba8Unorm` view. The native swapchain commonly reinterprets an sRGB base as unorm, while the candidate runner derives format from the underlying texture. Keep the gallery as the first consumer and verify view-format support before enabling other hosts. The stock path retains its single scene pass when there is no Loft row. Keel submits and presents after its sprites, boards and UI. [Frame composition](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/crates/keel_render/src/lib.rs#L647), [Scene passes](https://github.com/nbardy/room-runners-arena-lib/blob/b4cf34fe23898d8499bdceede044f3428fc20a72/keel/crates/keel_render/src/scene3d.rs#L807), [Host probe](https://github.com/nbardy/loft/blob/b1a4c26132eefc75547ba3e4e5b9ccb952b7b651/crates/loft-runner/examples/phase5_host.rs)

The exposed core is opaque and writes depth in Keel’s current packing. Ask Loft to write depth and use its strict `Less`, with a same-depth edge comparison scored against Keel’s `LessEqual`. ## Interop and first-light gates

- Follow the current spec’s `Runner::attach` → bundle load → `encode_into`. Keel allocates one `STORAGE | COPY_DST` row buffer and binds the same `Arc` with `bind_external_buffer`; it fills the row with one normal CPU ingress write per active frame. There is no GPU-to-GPU copy or readback for the handoff. Keep the handle stable across frames. `export_buffer` should return the same handle for the test. Rebind a replacement buffer in the test and check that the next draw sees it. A bad bind returns `AbiMismatch`. A successful resource change bumps its epoch; affected bind groups rebuild and pipelines remain independent of that epoch. The runner may re-record a bundle that captures the rebuilt groups. [Current ABI](../../../docs/spec/02_CORE_ABI_AND_LOWERING.md), [Zero-copy contract](../../../docs/spec/07_PLATFORM_POWER_EXTENSIONS.md#31-external-resources-and-bind-group-invalidation), [Keel embedding history](../../../docs/keel.md)
- Host attachment views go through `encode_into`. When a later material samples a Keel texture, use `bind_external_texture` on a distinct declared sampled table and validate format, dimensions, samples and usages. Do not sample a writable attachment in the same pass. Keel’s ordinary scene depth has `RENDER_ATTACHMENT` only, so sampling it requires a deliberate texture-usage change. For later Loft-generated pose or texture resources use `export_buffer` or `export_texture` and bind directly in Keel with the right usage and encoder ordering. [Platform extensions](../../../docs/spec/07_PLATFORM_POWER_EXTENSIONS.md#31-external-resources-and-bind-group-invalidation)
- Use a full Git revision of the root Loft runner with matching IR and `.loftb` codec. Loft `main` at `d9b33fc` has a compute-only `encode_into` and stub external binding. `loft/l5b` adds composition; `loft/i5-scored-fix` still has the bind stub. The published D1a candidate `b1a4c26132eefc75547ba3e4e5b9ccb952b7b651` has both attachment encoding and external binding and has run a two-pixel GPU host probe. Its combined suite and layer budget were still open. Use that full SHA for first light only, then repin after a released runner passes the same consumer gates. The older `loft-gpu` notes describe useful ownership rules and a different API. [D1a report](https://github.com/nbardy/loft/blob/b1a4c26132eefc75547ba3e4e5b9ccb952b7b651/agent_notes/2026-11-20_v1/lanes/d1a.md), [Phase 5 gate](../../../docs/spec/05_NUMBERS_AND_BUILD_ORDER.md)
- Keep the compiler outside the consumer’s dependency graph. Generate the small host-facing `.loftb` with the pinned codec offline and check the source and byte provenance into the lane. Both inspected locks resolve `wgpu`, `wgpu-core`, `wgpu-hal`, `wgpu-types`, `wgpu-naga-bridge` and `naga` singly at `30.0.1`. Keep that equality in the combined lock and exercise the native renderer feature separately from unfeatured `host_web` and the GPU-free server. Loft’s existing `tools/check_pins.sh` reads the legacy `rust/Cargo.lock`; the pilot compares the root candidate lock. [Consumer gates and commands](../../2026-11-20_codex/rr1.brief.md)

Require visible gold at the expected location, a foreground hull or deterministic opaque blocker to occlude it, unaffected pixels outside the projected core region, and Keel effects and UI in their existing order.
