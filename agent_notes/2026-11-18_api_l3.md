# API lane L3: one recorded identity (18 Nov 2026)

Design: `docs/proposals/2026-11-18_authoring_api.md` §7 "One recorded identity", §9 row L3. Branch `feat/api-l3`.

## What changed

- New `src/identity.ts`: the `Identity` record (`build`, `frame`, `device`), `identityId` (sha256 of canonical JSON:
  keys sorted, `-0` kept), and one producer per part: `buildOf(bundle)`, `frameOf(manifest, view, precision, drawn)`,
  `deviceOf(device)`. It imports only types and node, so it is on the file loader's closure
  (`tools/check_loader_closure.ts` passes).
- `src/cli/serve.ts`: a successful answer carries `identity` (the record without the frame's time) and each frame an
  `id`. `tier` and `precision` are gone from answers (folded into `identity`), failures included.
- `src/cli/main.ts`: `render`/`frames`/`clip` print `identity program … library … device …` once; `render`/`frames`
  print each frame's `id` beside its `rgba`. A scene compiled in-process is now lowered once in `main.ts` (bake,
  lower, `loadBundle`: what `createHost.load` does), so the bundle drawn is the bundle hashed.
- Docs: `docs/handoff_training.md` ("Identity" under `loft serve`, answer examples), `DESIGN.md` §3.2.
  `docs/api.md` unchanged (no public export added; regenerated output is identical).
- Tests: `tests/identity.test.ts` (new, 3 tests), `tests/serve.test.ts` (tier assertion replaced by id assertions).

## Where I diverged from the design, and why

1. **`build.graph` became `build.program`, the hash of the lowered bundle**, not a structural hash of the interned
   graph. The graph hash (plan step 8) does not exist yet, is a pre-lowering cache key, and is unavailable in the
   GPU process that answers serve (it never loads the compiler). The bundle is exactly what the GPU runs, so it is
   the stronger key for "same id, same pixels", and `render`'s compiled path and `render --artefact` agree on it.
   A scene compiled in-process with `cpu` tables is a named variant (`js-tables`, listing them): the hash does not
   cover JavaScript fills.
2. **`variant` and `style` are not fields.** They reach the GPU only through the bundle, so `program` covers them;
   as fields they could never change `id` on their own. So the manifest needs no new field and `manifest.ts` is
   unchanged.
3. **`library` hashes `src/`, not a git commit.** Creative vendors a copy without `.git`, and a dirty tree changes
   pixels. The compiler's effect is already in `program`; `library` covers the loader. 25 ms, once per process.
4. **`frame.camera` is the resolved camera**, not a name (fallback cameras and given camera objects have no name
   in the bundle). `params`/`inputs` list every declared one with defaults filled in, so an omitted default and an
   explicit one share an id. Added `drawn` (frame or still with samples/shutter/aperture) and `construction`, both
   of which change pixels and were missing from the design's record.
5. `device` is `{ runtime, adapter, driver }` (design: `backend`): runtime = Bun and bun-webgpu versions.

## The user's code

```
$ loft render examples/shell.ts --views three --size 128x96 --out a.webp
identity program 939f09f28b8d3597  library c0c7bf6e813d89cf  device apple / metal-3 / apple-m4
frame    11.4 ms  three  (4541 triangles drawn, 4 draw calls)  rgba bf2a8b3d154a4c1e  id aeb8abeb38a0f3bf
$ loft build examples/shell.ts --out d && loft render --artefact d --views three --size 128x96 --out b.webp
identity program 939f09f28b8d3597  library c0c7bf6e813d89cf  device apple / metal-3 / apple-m4
frame    13.7 ms  three  (4541 triangles drawn, 4 draw calls)  rgba bf2a8b3d154a4c1e  id aeb8abeb38a0f3bf
```

A serve answer: `{"id": "s1", "ok": true, "identity": {"build": …, "frame": …, "device": …}, "frames": [{"time": 0,
"file": …, "sha256": …, "id": …}], …}`.

## Pass/fail check (§9 L3), measured

| check | result |
|---|---|
| same request twice gives the same `id` and `rgba` | pass: serve A1/A2 (shell, 2 frames) equal ids and rgba; a fresh `loft frames` of the scene prints the same 2 ids |
| changing each field changes `id` | pass: all 28 leaves of a sample record mutated one at a time each change `id` (incl. 0 to -0); on a real draw, time, size, camera, param, input, construction and a 2-sample still each give a distinct id (7 of 7, no collisions); an explicit default keeps the id; serve plain/param/input give 3 distinct ids |
| a mixed request without `shader-f16` records `f32-fallback` | pass: mixed bundle on a featureless device records `frame.precision = "f32-fallback"`, `build.precision = "mixed"`; on the M4 with f16, `mixed`, with a different id |

Runs: `pnpm typecheck` clean; `bun test ./tests/identity.test.ts` 3/3 (1.6 s); `./tests/serve.test.ts`,
`./tests/files.test.ts`, `./tests/precision.test.ts` 11/11 (12 s); `bun tools/check_loader_closure.ts` clean.
Cost: `programOf` 0.52 ms for stormwing's 0.9 MB bundle (about 0.6 ms/MB; about 13 ms for a 22 MB scene, derived),
once per request.

## Left, and notes for the integrator

- **Verdicts do not carry `{ graph, arithmetic: "f64-twin/f32-encoded" }` yet.** That is `src/check.ts` (L2) and
  `src/cli/verdict.ts` (L4); checks run on the graph, not a bundle, so they need the plan-step-8 graph hash. Not done.
- `src/cli/run_files.ts` `openFiles` is now unused (`main.ts` opens the device itself to record it); delete it at merge.
- Creative's reader: creative's own training host (`creative/training/loft/host/`) does not read `tier` or
  `precision` from `loft serve` answers, so the pin bump needs no reader change. Anything else parsing serve answers
  must read `identity.frame.precision` instead of `precision`.
- `headlessHost` in `src/cli/load.ts` is still used by gallery, variants and tools; those print no identity.
