Plan: `docs/proposals/2026-11-19_lean_rust_loft.md` §4.1, §4.2 and §8.2 (wave 3, lane 3.3). Branch `feat/lr33`, cut

## What landed

- **`rust/crates/loft-draw`** (486 scc code lines; the ceiling is 900). It has two commands, one sum type and one
  dispatcher.
  - `loft-draw serve` is `loft serve`'s draw child. It reads resolved requests as JSON lines on stdin and writes
    `out/k.rgba` plus a sha256 for each frame. Each request gets one answer line, or a typed `Verdict` (`usage`, `load`,
    `environment` or `internal`) that maps the loader's `Error` exhaustively. A panic answers `internal`, and the
    server keeps going. A lost device exits 6. Precision `f32` and `mixed` each get their own device, so `f32` never
    sees `SHADER_F16`. That keeps `src/host/precision.ts`'s semantics.
  - `ready` carries `wire: 1`. The supervisor refuses any other value as `environment` and names the rebuild command.
    `Identity.device.runtime` names the executable by its sha256: the same binary gives the same pixels.
  - `loft-draw still DIR` is loft-view moved over: a PNG, `--frames N [--wait]` CPU and GPU timings, and
    `--pose-time`. `--pipeline-cache` and `--loads` are left for lane 4.2, which owns the Vulkan cache in loft-draw.
    This drops loft-view's `unsafe` call to `PipelineCache::open`.
- **`src/cli/serve.ts`**: `startRustDraw` has the same interface as `startDrawWorker`, so admission, compile slots,
  deadlines and `closeWith` are unchanged. The supervisor does the work that needs the bundle: `readBundle` with
  `--limits`, `--check`, param, input and camera checks, and the identity record. Only resolved data crosses the
  pipe, as `canonical()` JSON, which keeps -0. `cache` became optional in `Answer`, because the wgpu path has no Dawn
  object cache. +101/−5 lines; the ceiling is 350.
- **`tests/serve.rust.test.ts`** replaces the three serve tests that reach into Dawn. The `--check` hook stops
  (`SIGSTOP`) or kills the child by pid, which stands in for a hung driver or a crash.

## Not done

- **`loft-web`, `viewer/main.ts`, `src/cli/dev.ts`** are blocked on lane 3.2's async loader. `loft-loader` passes
  `cargo check --target wasm32-unknown-unknown` (11.7 s). It still cannot run on WebGPU:
  - `scoped` and `harvest` use `pollster::block_on` on error scopes and maps, which never resolve inside the browser's
    event loop;
  - it has no `webgpu` feature;
  - `read_dir` uses `std::fs`, and the browser needs `Bundle::from_bytes`.

  Keel step 2 is exactly this. Once `loft-gpu` loads asynchronously, the glue is about 150 lines (exports `load(bytes)`,
  `set_param`, `set_time`, `frame(canvas)`), and `dev.ts` serves the built directory.
- **`loft render/frames/clip/profile` routing**: `main.ts` belongs to the integrator. The design:
  - under `rust`, `open()` builds into a private directory the way serve does, then sends serve requests;
  - `profile` maps to `loft-draw still --frames N --wait --pose-time`;
  - the protocol needs per-frame inputs for `--sweep` and clip. Wire 2 should change `times` to
    `frames: [{time, inputs}]`, and a request should not reload per frame;
  - `--samples` stills (`host/still.ts` accumulation) have no loader path, so they should be a `usage` refusal under
    `rust` until 3.1/3.2 add one.
