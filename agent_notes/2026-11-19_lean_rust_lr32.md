## What

`rust/crates/loft-gpu`: **1,114 scc code lines** after rustfmt (ceiling 1,500): `lib.rs` (the host), `validate.rs`,
`cache.rs` (moved from loft-loader). Tests in `tests/it/main.rs`.

- `Loft::load(device, queue, bytes, ask, canvases, cache)` is async (no pollster in the crate, so it works on wasm). It
  reads the file through `Bundle::read`, which refuses another format by name. It then picks what runs (`Mixed` only
  with `SHADER_F16`, otherwise `F32`) and runs `validate`. Only after that does it create every object inside one error
  scope, with all compute pipelines and every render pipeline for each `Canvas` (colour format, depth format, samples).
- `validate(&bundle, precision, &limits)` does the following before any GPU object exists (Keel step 6):
  - checks every id, and the shape each role needs (rows, colour or depth texture);
  - checks init section lengths, `Init::By` kernels, `Steps` (dt > 0, `Every(0)`, one rows write) and input arity;
  - checks the frame uniform, storage and texture sizes against the device's limits;
  - runs Naga on every module under the precision that will run.
  Author WGSL is refused as `Scene { Wgsl { line } }`; library WGSL and every other bad bundle as `Load(Invalid(msg))`.
- `encode_into(device, queue, encoder, &View)` records one frame in this order:
  1. write the frame uniform;
  2. one compute pass of `Frame` kernels;
  3. live `Steps(Latest)` to n = floor((t - from)/dt), rewinding from the init when time goes back;
  4. the passes in order.
  `View` holds the caller's colour and depth, `Owner::{Loft, Caller}` and `Layers::{All, Subject}`. With `Owner::Caller`
  every view attachment is `LoadOp::Load`, so nothing is cleared. Offscreen and shadow passes own their targets and
  clear as `Pass.clear` says. Compose entries are Screen draws (ground before the pass's draws, outline after).
- `Steps(Every(k))` runs every step at load and keeps state `first + j·k` in slot j (the layout of loft-core
  `kernel::kept`). Step i sees a frame whose time is `from + i·dt`. Each step has its own slot in a dynamic-offset
  uniform, so all steps go into one submit.
- Timestamps: `set_timestamps(QuerySet)`, with the kernel pass at 0/1 and render pass k at 2+2k/3+2k, as in the loader.
  `frame_key(camera, size)` and `build()` give `Identity`'s parts. `PipelineCache` is moved over, still `unsafe open`;
  lane 4.1 makes it safe.
- Binding contract (in `lib.rs`'s docs; 3.1 and the driver must emit against it):
  - group 0 is emit's `Frame` uniform: param k is component k, input j is vec4 j;
  - group 1 binding k is `Module.reads[k]` (read-only storage, or a `textureLoad` texture);
  - group 2 binding k is `Kernel.writes[k]` (read-write storage, or a write-only storage texture);
  - Map is `@workgroup_size(64)` and Scan is one invocation;
  - a draw module has exactly one `@vertex` entry, and `shade` is its fragment;
  - vertex counts per `Cover` are listed in the docs.

## Left

- **LOD plan not ported.** `Bundle` has no per-draw detail (levels, slot, radius) and no bounds readback, so
  loft-loader's `plan.rs` has nothing to read. That needs a `Draw` field (3.1 / loft-ir) and then about 200 lines here.
  Until then a Grid draws at its authored u×v.
- **Cameras.** The host ignores `Pass.camera`. A host camera is set as the view camera's inputs (`set_input`), as §1.5
  says. Reading the camera back for LOD comes with the LOD port.
- **Pipelines compile sequentially.** The loader's 8-thread `par_map` was dropped. Restore it if load time matters
  (wgpu error scopes are per thread).
- **Author WGSL has no site.** `Scene{Wgsl}` carries the module line with `site: None`, because the bundle has no
  per-module line table yet.
- **Not built:**
  - samplers (textures are `textureLoad` only);
  - MSAA resolve for offscreen passes;
  - textures written by `Steps` kernels (refused by name);
  - kernels reading view-sized textures before the first frame (they see a 1×1 texture).
- The `Keep::Every` contract is that readers choose and replay the kept states. It and the step time `from + i·dt` are
  conventions that 3.1 and the driver must match. Change them here and in `lib.rs`'s docs together.
