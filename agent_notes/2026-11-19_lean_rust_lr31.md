# Lane 3.1: draws (lr31, 19 Nov 2026)

Plan: `docs/proposals/2026-11-19_lean_rust_loft.md` §1.5, §1.6, §8.2 (lane 3.1). Branch `feat/lr31`, based on `96e36d8`.

## What

`rust/crates/loft-core/src/draw/mod.rs` and `rust/crates/loft-core/wgsl/*.wgsl`. They come to 523 scc code lines: 321
Rust and 202 WGSL, against a ceiling of 2,000.

- `draw::lower(g, at, draws, media, passes) -> Lowered { modules, names, draws, media, passes }`. Each draw becomes one
  WGSL module: emit's graph module (lane 2.2), then `view.wgsl`, then the glue, then the templates for its cover. Naga
  checks every module. The outputs are `loft_ir::bundle::{Draw, Medium, Pass}`.
- The compile-side `Draw`/`Cover`/`Prim`/`Find`/`Medium`/`Pass` are the plan's §1.5/§1.6 types. They still carry Fn
  decl ids, which the bundle types cannot. Resource ids are Kernel decls, mapped through layout's `at`.
- **One template per job, with no per-kind branch.** There is one `Ray` template (`ray.wgsl` proxy vertex stage,
  `hit.wgsl` colour and depth entries). The vertex stages are `grid`, `mesh` and `quads`, with one shared `lit` fragment
  stage. `Screen` has its own template. A medium has two integrations, `march.wgsl` and `gauss.wgsl` (closed form with
  erf). Both expose `loft_tr{k}(p, dir, reach, n)` and `loft_scatter{k}`.
- **What content supplies (graph functions):**
  - `paint(p, n, id) -> rgba`;
  - `hit(o, d, span, width) -> (normal, t)`, where t < 0 is a miss and the width at t is `width.x + width.y * t`, as in
    TS `Ray.width`;
  - grid `place(uv, id) -> pos`;
  - quads `place(id) -> (centre, radius)`;
  - `density(p)`;
  - `outline(colour, q) -> (ink, width)`.
  
  A medium's albedo, phase and light are its draw's paint.
- **The veil rule, decided once.** A draw that writes no depth (glow, specks, rain) cannot be seen by a medium's
  scene-depth clip, so its colour is multiplied by `loft_tr` of every medium in its colour passes. A draw that writes
  depth is veiled by the medium drawn over it. There is no `specksVeil`/`specksVolumeVeil` pair and no veil flag.
- **Composer.** The ground is the `hit.wgsl` template with a full-screen vertex stage and an unbounded proxy. Ink is
  `outline.wgsl`, the TS `INK_POST` search. Each exists only in `compose`.

## Host contract (for lane 3.2)

- `@group(0) @binding(1)` is `View { clip_from_world, world_from_clip, size: (w, h, 1/w, 1/h), sun: dir }`, beside
  emit's `Frame` at binding 0. Rays start at the near plane, so perspective and orthographic views (shadow maps) are one
  case.
- `@group(2) @binding(k)` is declared in order by the module. A row resource is `g{res}`, an `array<vec4<f32>>` of
  bundle resource `res`. The textures are `under`, `scene_colour` and `scene_depth` (`texture_depth_2d`). The host
  finds bindings by name with Naga reflection or auto layout.
- **Vertex counts.**

  | Cover | Vertices | Instances |
  |---|---|---|
  | Grid | u·v·6 | `count` |
  | Mesh | rows of the resource / 2 | `count` |
  | Quads | 6 | `count` |
  | Ray | 36 | 1 for Box, rows for Instances |
  | Screen and composer | 3 | 1 |
- The Ray proxy box is wound inward. With back faces culled, each pixel runs once, from inside or outside.
- Draw entries:
  - every module has `vs`;
  - `fs` writes colour, plus `frag_depth` for Ray hits;
  - `fs_depth` is a Ray's shadow entry.
- Draw order within a pass:
  1. opaque draws;
  2. a copy of depth to `scene_depth`;
  3. media, premultiplied alpha;
  4. draws that write no depth.

## What is left

- **The TS half of the lane is not done.** `src/draw/*.ts` and `src/soft/*` must be rewritten as library hit, place
  and paint graph functions: the five tracers as hit functions over `march.ts`, and the four particle drawables as
  quads place functions. The TS emitter still renders from those files until the cutover, and recorded draw decls do
  not decode yet.
- **Parity risks to score once the corpus runs:**
  - (1) `gauss.wgsl` composites Gaussians front to back in kernel order. TS `draw.density` deposits into fixed depth
    bins and uses a third of a blob's own depth for self-shadow. If storm/stormfront fail rule 3, the bins move into
    the template, still as one integration.
  - (2) The ink step is `3 × ink width at q`. TS uses the style's `outline_world()`.
  - (3) TS `march.ts`'s secant refinement and near-miss gap belong to the hit function (content), as the plan's risk
    table says.
- Picture parity, the shared-module count and the per-scene Naga run of real bundles. All of them wait on decoding jobs
  and on lane 3.2.
