## What

- `rust/crates/loft-core/src/check.rs`: §1.7's `Check`/`Formula`/`Quant`/`Strategy`/`Verdict`/`Truth`/`Why`/`Scope`
  over the f32 tape, and `check(ssa, held, &Check)`. `Formula` is recursive (`And`/`Or`/`Not` of quantified
  formulas, nested quantifiers); a run of one kind is one joint search. The search is `src/ranged.ts`'s (best first,
  middles and corners, pattern polish, nested searches started from the enclosing witness, inner witnesses that move
  along a split leaf). Budgets are boxes (work units), not wall time, so a budget refusal is deterministic.
  `Strategy::Sample { n }` is the sampled scope; it can never print "holds" as a proof (`Scope::Sampled`).
- `rust/crates/loft-core/src/cache.rs`: the program cache. `key(job, options, commit)` = sha256 of the three,
  length-prefixed; `through(dir, key, program)` returns the stored result or runs `program` and stores it
  (temp file + rename). Refusals are not stored.
- `rust/crates/loft-core/dump_checks.ts` + `tests/it/analyses.rs`: the bridge and the check. Until the wire repair
  (wave 1 integration note) lets recorder jobs decode, the dumper walks the TS graph (fetches at constant entries
  inlined from their table program and constant-count loops unrolled, as `src/interval.ts` does) and records the TS
  `decide` result beside each graph.
- Lines (scc code): check.rs + cache.rs = 784 Rust; test 140, dumper 109. Ceiling 1,400 (solve not yet written).

**New here (DERIVATION; not inherited from the TS):** the correlation the TS kept with affine forms comes from a
centred form. Over a box X, twin(x) is in real(m) + sum_j D_j (X_j - m_j) +- E: D_j encloses the derivative (`grad`
appended once, enclosed over X), real(m) the padded point enclosure, E the twin's f32 rounding over X as a forward
running-error bound (e_r = pad_r + sum_k |d op/d arg_k| e_k, partials enclosed by each atom's own derivative rule).
It is intersected with the plain enclosure, and used only where every jump in the margin's cone (floor, comparisons,
select, rem, atan2's cut) is decided over X; abs/min/max are Lipschitz and their `sign`/`select` derivative
enclosures contain the subgradients. A moving inner witness (`Track`) is a prelude in the same program:
x_k = R_k + sum_j Q_kj (R_j - M_j), so d/dy along the track is one derivative and keeps the cancellation
(d/dy |t(y) - 1.7y| along t = c + 1.7(y - m) encloses to 0, where two separate partials give [-3.4, 3.4]).

## Found on the way (for lane 1.3's owner, `interval.rs`)

Two enclosures failed where the TS's did not; check.rs's prelude rewrites around both, keeping the twin's bits:

1. `x * x` encloses as a product of two intervals: [-w², w²] for x in [-w, w] (TS has `sqrC`). Rewritten as
   `|x| * |x|`.
2. The fold pads [0, w] below zero (pad at 0 is 2·2⁻¹⁴⁹), so `sqrt` of a sum of squares is `OutsideDomain` wherever
   the difference meets 0: every `distance` minimum (the claw's -0.35 point) was unprovable. Rewritten as
   `sqrt(max(s, 0))` when s is structurally a sum of squares (same value). A square rule and a nonnegative-result
   clamp in `interval.rs` would make both rewrites unnecessary.

## Left

- **solve.rs.** Not written. Two decisions it needs: (1) The optimizer keeps f64 (§3.4) but the tape is f32; f32
  hold noise (6e-8 relative, ~1e-7 m on heron's metres) is above `AIM` 1e-8 and `MET` 1e-6 is close. An f64
  evaluation already exists without a second table: each `ATOMS` row's interval rule at a point box is the f64
  operation (pad aside), so `solve` can evaluate holds in f64 from the same rows. (2) Its input: heron's holds read
  `bspline` rows and need the decode of `row`/`Call`/`Loop` that no wave-1 lane wrote. feat/rust-core's `solve.rs`
  (774 lines) is the kernel to port once (1) and (2) are settled; heron is the only scoring case.
- **Corpus verdicts** need the wire repair (wave 1 integration note: lanes 1.1 and 1.2 encode §3.2 differently)
  and a graph -> tape lowering with `Fetch`/`Loop`; then `dump_checks.ts` is deleted and the corpus runs through
  `run(Check, spans)`.
- `Why::Opaque(RawId)` and `Why::State(ResId)` are the lowering's refusals (a raw function or `Steps` state has no
  tape), so they are not in check.rs's `Why` yet; the driver adds them when it lowers.
- Refusals use `SceneFault::Unsupported { what }` with the fix in the text (dependent range end, reversed or
  non-finite range, a leaf bound twice on one path). Typed variants belong in loft-ir's `SceneFault` (lane 1.1 owner).
- A track's point is real-valued; the twin only takes f32 leaves, so a witness is up to one ulp(t)·|df/dt| off the
  enclosed line. Not charged to E (it is far below 1e-4 here); noted, not proven.
