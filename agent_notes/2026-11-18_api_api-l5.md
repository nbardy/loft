# Lane L5 (slots): what changed, the user's code, the check (18 Nov 2026)

Design: `docs/proposals/2026-11-18_authoring_api.md` §3, §8 items 1, 2, 8 and the L5 row of §9. Branch `feat/api-l5`.

## What changed

- **Slots never pass time.** `draw.volume`'s density, albedo and emission are `(p)`; `draw.points`' speck is `(i)`.
  An author reads `time`. Inside the drawable the expression is taken at a time `t` by `substitute(time -> t)`, so the
  view march, the shadow march, the veil and `stretch` (the path a moment earlier) still sample it at their own time.
- **`draw.points` is the speck drawable** (was `draw.specks`; options type `PointsOptions`, was `SpecksOptions`).
  The old instancer `draw.points(name, points, thing)` is folded into `draw.posed`: `points(n, spec)` now returns
  poses (no turn, an even size), so the 25 callers changed one word. `Points`, `Instanceable`, `instanced()` and
  `posesOf` are deleted; `warp.points` maps poses.
- **A `draw.volume` veils specks.** `veil` takes a `draw.density` or a `draw.volume` drawable (a three-variant sum
  type, classified once by `veilOf`). For a volume it is the volume's own march from the ray's entry into its box to
  the speck. With 32,768 specks or more, and volume functions a compute stage can run (no table, row, input, param,
  derivative, texture sample or scene depth), a pose table fills a 32³ grid of that march for the main camera, as the
  density veil does; otherwise each speck pixel marches.
- **`src/lib/wgsl.ts` deleted, `wgslFn` gone.** `fwidth`, `viewDir`, `eyePosition`, `pixelWorld` are one-line raw
  functions in `wgsl` text in `src/lib/screen.ts` (internal; the twin now refuses them by name and line). Examples
  that used them write the same one-liner. `styles.ts` no longer exports `fwidth`, `pixelWorld`, `wgslFn`.
- **One entry.** `src/index.ts` exports every public name, `src/lib` and `src/spacetime` included. Nine names two
  layers share resolve to the core's meaning (`compose`, `extrude`, `round`, `Field`, `Frame`, `Key`, `Placed`,
  `Plane`, `Part`); the sdf/fold/list-tree meanings stay importable from `src/lib/index.ts`.
- **`draw.density` defaults.** Only `bounds` is required: `sun` [1, 1, 1], `sky` 0.8, `forward` 0.3, `shadowing` 0.8,
  `detail` none, `haze` 0 (the common values across the callers).
- Docs: guide (specks, volume, raw functions, the wgslFn snippet rewritten in text), errors (4 rows), DESIGN (§2 note,
  draw table, §8.3 veil and its cost), `docs/api.md` regenerated. New example `examples/dust_veil.ts` (§3's user
  code), still `agent_notes/2026-11-18_api_api-l5/dust_veil.webp`.

## Where the design was wrong, and what I did

1. *"replace fwidth, viewDir, eyePosition, pixelWorld with text raw functions in their callers"*: done for those four,
   but in one internal module rather than in each of ~20 callers (identical text is one function; a copy per file
   buys nothing). The other `wgslFn` uses (the sea's contact band, papercraft's facets, light's long direction,
   whitewater's slope) became plain `LibFn` values: they read compiler-owned `loft_` names (`loft_detail`,
   `LOFT_DETAIL_SLOT`) that text refuses, and they stay byte-identical.
2. *"fold the old draw.points into draw.posed"*: rather than make `draw.posed` accept two set types, `points()` returns
   poses. One type, one drawable, no classification.
3. The design wrote a per-pixel volume veil as the follow-up. Measured, that is 120.8 ms for 100,000 grains: so the
   grid cache, as the density veil has.

## The user's code (examples/dust_veil.ts)

```ts
const fx = wgsl`
struct Grain { at: vec3f, radius: f32, colour: vec3f, opacity: f32 }
fn grain(i: f32) -> Grain { let q = flight(i, time); ... }
fn dust(p: vec3f) -> f32 { ... noise3(p * 1.7 - vec3(0.4 * time, 0.0, 0.0)) ... }`;
const cloud = draw.volume("dust", fx.dust!, { bounds: { min: [-2, 0, -5], max: [6, 5, 5] }, steps: 64, g: 0.6, albedo: [0.6, 0.25, 0.1] });
const grains = draw.points("grains", 100_000, fx.grain!, { stretch: 0.004, veil: cloud });
```

## The pass/fail check, measured

- **Artefacts.** All 67 example scenes built before (`45219a4`) and after; the 57 non-scene modules fail to build
  identically before and after (no default export). 6 byte-identical. 59 identical after renaming the four raw
  functions (`loft_fwidth` -> `pixel_rate_d933d0c5`, `loft_view_dir` -> `toward_point_058452ba`, `loft_eye` ->
  `eye_point_f2e7b46b`, `loft_pixel_world` -> `pixel_size_6659a6cb`; text names are content-hashed). The two files
  whose signatures changed, `examples/spray_burst.ts` and `examples/volume_dust.ts`, are identical after those renames
  and renumbering the emitted value names (`e214` -> first-seen order): substituting `time` makes the same graph with
  other node ids. Comparison: manifest with module texts in place of chunk hashes, plus `bin/`, per scene.
- **`tools/check_snippets.ts`**: 130 names, 52 commands, 19 modules typechecked, 13 scenes rendered, 0 failed.
- **Grains dim inside a `draw.volume` by a measured share** (`tests/soft.specks.test.ts`): a black slab of extinction
  ln2/2 between z = -2 and 2; white-minus-black grain contrast 183, 91, 46 for grains in front, at the centre and
  behind: shares 0.497 and 0.251 against the predicted 0.500 and 0.250, the same on the marched path (3 grains) and
  the grid path (32,768).
- **Cost** (`loft profile examples/dust_veil.ts --view game`, 1280x800, 100,000 grains, 64 steps): grains 1.56 ms
  with the grid (pose stages 0.60 ms, shadows included), 120.8 ms marching per pixel, 1.13 ms unveiled.
- `pnpm typecheck` clean; focused tests 80 pass, 0 fail (soft.specks, volume.gpu, compile.gpu, compile.shadows,
  ranged, lib.util, text, map.posed, soft.render, soft.gauss, styles.gpu, style.pbr.gpu, soft.storm, similar,
  lib.fold.props); `tools/check_loader_closure.ts` passes. The full suite is the integrator's.
