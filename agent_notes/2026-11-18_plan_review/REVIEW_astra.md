# Loft plan review · astra · 18 November 2026

## Verdict

**Change the plan. Fund the graph, the compiled renderer, and one whole-scene interpreter experiment.**  
Fix ranged checks before paying a model for their verdicts. They currently certify false propositions.  
Keep equations, keys, and solved splines as peers. A local search failure should never tell an author to delete a feasible hold.  
Move Linux and the actual training contract ahead of interpreter batching, background promotion, and cache research.  
Release further interpreter funding against scored samples per GPU-hour and CPU-second on that worker.

## Defects in landed code

**1. A ranged proof can contradict the CPU twin on the very point it certifies.** I ran `e = mix(2**56, 1, time)` at time 1. `Probe.scalar(e, 1)` returned 0. The ranged decision for `always([time, 1, 1], ge(e, 0.5))` returned true, with margin 511.5 and a witness at 1. The CPU computes `a + (b - a) * t`. Subtracting 1 from this power of two loses the 1 in double precision. The interval rule intersects its result with the hull of the two endpoints, which excludes the CPU result. The decision then publishes the upper bound as the value at the witness. This fails without a GPU, a transcendental function, or uncertainty about the time. Specify the arithmetic being certified, enclose the actual evaluation order for that arithmetic, and replay the witness independently. Return the observed value and the proof bounds as distinct quantities. Add this case to the enclosure tests, which currently allow slack proportional to the value. (`src/expr.ts:1114`, `src/interval.ts:198`, `src/ranged.ts:205`, `tests/ranged.test.ts:19`.)

**2. Quantification changes the meaning of accepted expressions.** Two independent failures reproduced on main.

- At the singleton time 0, both `gt(time, 0)` and `not(ge(time, 0))` returned `holds: true`. Strictness is erased when comparisons become margins, and both signs of zero pass. This changes a contact or deadline exactly where an author cares about equality. Preserve Boolean truth separately from robustness at zero, including through negation and quantifiers. A conservative undecided boundary is acceptable where truth cannot be established. (`src/ranged.ts:105`, `src/ranged.ts:211`.)
- For all `t` in [0,1] and all `x` in [0,t], the assertion `x <= 0.5` returned true with margin +0.5. The actual worst margin is −0.5 at `t = x = 1`. The API accepts expressions as endpoints, merges adjacent universal quantifiers, then evaluates endpoints with `probe.scalar` at its default time 0. The search proves a property of the wrong domain. Reject endpoints that depend on bound leaves until dependent domains are implemented. Keep expression endpoints that depend only on held values. (`src/ranged.ts:22`, `src/ranged.ts:126`, `src/ranged.ts:247`, `src/check.ts:66`.)

**3. The training-facing check loses the difference between failure and exhaustion.** The structured `decide` result distinguishes them. The standard `run` adapter maps both to `pass: false`, and the CLI counts both as failed. Unsupported operators take a third path, a scene exception. The box budget also fails as a hard work bound. My one-box request for `always([time,0,1], ge(time,0))` used 25 boxes and reported “finished”. Corners, witness polishing and recursive calls spend work before the cap is consulted. Carry verdict, bounds, witness and stop reason through the public check result. Charge every enclosure against the shared budget before evaluating it. Keep unsupported and exhausted checks out of negative training labels. Existing `staysClear` still defaults to 60 Hz and excludes its end time. Preserve that endpoint convention or version the change when supplying a ranged implementation. (`src/ranged.ts:147`, `src/ranged.ts:278`, `src/ranged.ts:342`, `src/interval.ts:81`, `src/cli/check.ts:36`, `src/check.ts:263`.)

**4. Solver success can include an undefined hold, and solver failure can reject an exact solution.** With one four-coefficient spline, a point hold fixing it to zero at the start, and `atLeast(sqrt(0.5 - time), 0)` over [0,1], the solver returned a worst violation of **0**. The hold evaluates to NaN at time 1, on its own verification grid. Comparisons against NaN skip failure and peak detection. Reject non-finite residuals and derivatives at evaluation, with the hold and time in the error. Separately, `equal(x*x, 1, {at: 0.5})` with `spline(4)` and a jerk preference reported “cannot all be met”. Starting the same spline at 1 succeeded with zero miss. At the zero start the constraint's gradient vanishes. The deletion filter uses the same local search and cannot turn this into an infeasibility certificate. Return the existing `unsolved` result with a start-dependent diagnostic. Reserve `infeasible` for a certified contradiction. Label the final interval residual as sampled and apply a ranged check when a continuous guarantee is requested. (`src/geom/solve.ts:340`, `src/geom/solve.ts:694`, `src/geom/solve.ts:729`, `src/geom/solve.ts:775`.)

**5. The warm server lacks request ownership at two boundaries.** A scene request uses the caller's `out/artefact` as its build directory. Concurrent requests sharing `out` can replace each other's bundle between compile and draw. Frame files also have the same numeric names. The existing A/B/A test assigns a different output directory to each request. Reserve the destination while a request is active or assign immutable per-request directories, and test overlapping destinations. At input, `readBundle` reads the referenced files before the check hook sees them. The Creative host already stages a private, size-limited inbox and supervises restart. Make that handoff part of the farm contract, or validate names and sizes before file reads in the loader. Also bound the number of admitted requests waiting for the serial draw. These are source findings. I did not run a concurrency or device-loss experiment. (`src/cli/serve.ts:194`, `src/cli/serve.ts:205`, `src/cli/serve.ts:229`, `src/cli/serve.ts:275`, `src/host/files.ts:26` and `:53`, Creative vendor `RESULT.md:80`.)

**6. Several PBR substitutions stop at a private boundary.** The public GGX, visibility and Fresnel functions are genuinely reusable. But setting the distribution to zero removes direct specular while the environment still uses the private albedo fit for GGX/Smith. An artist can see a sky reflection from a lobe they removed. Let the environment contribution own its matching weight, with the present fit as the default. Test the zero lobe under environment-only lighting. Also, a GPU-only sky with a custom environment still failed in my constructor test. The unconditional CPU evaluation of the clear colour reads the sky and tone map before the style exists. Derive the clear colour independently or accept an explicit clear colour for this case. The furnace test also keeps the sun amount at 1 and puts it behind the receiving normals. At the zero sun amount specified in the PBR note, the assembled style multiplies even a custom uniform sky by zero. Decide whether sky radiance is authored independently of sunlight and test that convention explicitly (`tests/style.pbr.gpu.test.ts:57`). Finally, the style sees each local lamp's amount already multiplied by shadow visibility. Ink responding to a shadow edge cannot recover visibility separately from lamp attenuation. Expose the unshadowed arrival and visibility where the fold evaluates the light, and use their product for existing styles. (`src/style/pbr.ts:37`, `src/style/pbr.ts:101`, `src/style/pbr.ts:112`, `src/light.ts:196`; proposal §4.)

## Design defects, in funding priority order

**1. The speed gate measures the wrong unit of work.** Step 2 passed its declared test for two full-screen paint functions. Step 5 commits to full coverage, batching and promotion on the strength of that result. At `be17739`, `tools/interp/bytecode.ts:93` refuses parameters, curve rows, table fetches and iteration. Its fixed tape keeps dispatch uniform across a quad. A folded marcher with early exits, a pose-table scan, and a material using screen derivatives exercise different constraints. A library-owned raw shader can also force fallback in a scene whose author used only expressions. Count actual pipeline misses and fallback reasons by stage on training draws. Try fixed host stages plus interpreted expression roots through the file loader. A versioned tape needs operand types, storage bounds and a work bound the loader can validate. One complete scene should establish which stages are worth interpreting before a general implementation is funded. (§3, steps 2 and 5.)

**2. The authoring promise ends at the trainer's import boundary.** I checked Creative `7c9c6963`. Its gitlink is Loft `b5cd367`. Its vendor helper list admits `scene`, `lamp`, `toon` and selected algebra, and omits `march`, `draw`, `pbr` and `solve`. The compiler enforces that list. On Loft itself, `always` and `eventually` still require an internal import. A model given the proposed brief cannot use those public examples in the cited training environment. Pin both sides for the trial and generate the model brief from the active training contract. Exercise an authored field, custom style and direct polynomial in that path. Define which richer render features the sandbox admits and report unsupported capabilities distinctly. A compiled fallback only helps code that reached the compiler. (§§2, 7b; `src/checks.ts:3`; Creative `training/loft/host/allowed-imports.json` and `compile.ts:31`.)

**3. Determinism conflicts with a history-dependent tier switch.** The probe observed a maximum channel difference of 0.000116 between two implementations on one adapter. Agreement within 1/255 permits different quantized bytes. A background promotion triggered by earlier requests can therefore change replay, even on the same library, device and driver. Fix the training tier for each sample and record it alongside the artefact digest, parameters, inputs, camera, time, size and backend versions. Check byte equality within each tier and evaluate cross-tier reward agreement separately. Correct rounding of three transcendentals leaves arithmetic contraction, f32 stores, table fills and predicate boundaries unresolved. Specify those semantics for the subset carrying proofs. (§3, §6.5; probe note lines 38–43.)

**4. A cache “by meaning” promises more than the consumer needs.** Algebraic reassociation can change a rounded value or a branch. Matching renders at four times establishes equality only at those views, inputs and times. The graph also excludes part of a drawable's raw source and host schedule. Cache the exact compiled inputs or serialized products first, including referenced constants, layouts, shader chunks and version. Measure hit rate on fresh generations. Require an equivalence rule to preserve the declared numeric semantics before crediting it with a cache hit. Defer “no visible change” to a named set of observations. (§7, step 8.)

**5. A signed margin needs a scale, and a picture fact needs an observable.** Multiplying a clearance inequality by 100 preserves every passing scene while multiplying its dense reward by 100. Taking the minimum of a warning time in seconds and a gap in metres also makes the ranking depend on the chosen units. Let the task own the predicate, physical units and normalization before combining scores. In §6.4, define visible share for a particular camera, time, geometry representation and opacity convention. A custom discard, translucent water or a post outline can change pixel coverage while leaving skeletons identical. On the 26 labelled cases, compare an analytic proxy against a reference mask and record the disagreements. Promise exactness only for forms and operations the visibility calculation actually evaluates. (§§1, 6, 6.4.)

## Against the five binding positions

| Position | Assessment |
|---|---|
| Programmable motion | **Honoured in Loft.** Equations and keys remain ordinary expressions. The heron uses a hand-written arc to initialize the solver and uses the returned curves to place a rigid body. Keep optional solving out of the cost of direct motion. The solver's derivative and spline-family restrictions belong to that producer alone. |
| Arbitrary maths and algorithms | **Partly honoured.** `draw.traced`, `march`, meshes and raw WGSL give authors substantial freedom. The host fixes the frame stages, some CPU-filled tables cannot cross the file boundary, and the actual trainer admits a smaller vocabulary. Publish coverage by execution path and retain an end-to-end space-folding example. |
| User styles and replaceable PBR | **Partly honoured.** A custom `Style` and exported parts work today. The private environment weight, CPU-only sky setup and pre-shadowed arrivals constrain ordinary substitutions. A fixed interpreter BRDF would make those restrictions permanent unless custom terms can travel as expressions or explicitly use tier C. |
| Faster, reliable, deterministic training | **Unproven.** Warm compiled replay is a credible baseline. The measured paint timings, Linux deployment, reward arithmetic and solver/check budgets answer different questions. Measure the completed reward-bearing sample and its repeatability. |
| Every name buys a capability | **Mostly honoured.** Retain `equal` and `atLeast` over user expressions. The proposed plant/land/clear vocabulary would duplicate them. A structured witness earns its place. Ship it through the existing check command before adding a query language and three separate commands. |

## Numbers behind the decision

The following measurements are the authors' recorded results. The arithmetic is mine.

- **Historical CPU share.** Creative's 16 Nov `RESOURCES.md` gives 5.96 Bun CPU-seconds for modules/pipelines, 10.5 compiler-service CPU-seconds and 9.4 total Bun CPU-seconds. Thus (5.96 + 10.5)/(9.4 + 10.5) = **82.7%**. Deleting that work entirely gives an optimistic **5.8× CPU speedup** for that frozen workload. It says nothing quantitative about today's warm Vulkan wall time. The quoted **0.447–0.787 s** vendor warm figures are immediate same-program repeats, one subject frame, excluding the blank and encoding. Loft's separate four-frame serve benchmark reports **0.96 s** warm-server wall in round two and **0.55 s** on repeat. (§3; Creative vendor `RESULT.md:117`; Loft serve note, “Measurements”.)
- **Paint break-even.** With the fixed pipeline resident, four-frame savings equal compiled paint setup minus upload/lowering minus four times the GPU penalty. At the probe's reported best frame times, cold crab saves 34.42 − 0.413 − 4(2.032 − 0.0328) = **26.01 ms**. Cold water saves **28.98 ms** by the same calculation. Substituting the warm setup measurements of 1.70 and 4.57 ms yields **losses of 6.71 and 17.97 ms**. Sixteen full-screen water evaluations alone cost 16 × 5.571 = **89.14 ms**, leaving **10.86 ms** of the proposed 100 ms for everything else. The proposal's own 10–30 ms folded-march estimate implies **160–480 ms** for sixteen such frames. Both calculations depend on coverage. Whole-scene setup and isolated paint setup cannot be exchanged in this equation. (Probe note lines 17–29, 43.)
- **Reward work can dominate a successful renderer.** Recorded checks took 93 ms for the claw and 91.7 s for the parameterized serpent. The base heron solve took 5.0 s at build. At a 100 ms sample target those are **0.93, 917 and 50 sample budgets** respectively, before their other work. They describe three separate workloads. Record interval width and witness quality against CPU spent, and distinguish optional offline certification from checks required for each training reward. (Ranged note, “Results”; solve note, “Demos”.)

## Missing experiments and order of work

1. **Repair the reward path from expression to trainer receipt.** Replay the strict boundary, dependent range, cancellation, non-finite hold and feasible stationary-start cases above through the public entry points. Pass when no false claim survives, independently evaluated witness values agree with the reported observations, budgets hold under nesting, and an exhausted or unsupported check is distinguishable from a violated constraint all the way to scoring. Keep the tunnelling and landing examples as positive controls. Test what the predicate represents, too. The heron checks five torso stations and three bill stations (`examples/second/heron_leap.ts:62`). Continuous time coverage of those points leaves spatial gaps. Include a contact between stations and require the reward to declare its geometric coverage.
2. **Bring step 6 forward and build a costed Linux tier-C baseline.** Run a pinned vendor training configuration through subject, blank, geometry, checks and final receipt on the farm adapter. Include original programs, new edits, repeated frames in shuffled order and a worker restart. Pass when replay hashes match for every identical request, the next good sample survives a failed worker, host failures receive no scene penalty, and receipts expose compile, solve, check, queue, GPU and output costs. Include fixed-owner checks and held-out scene parameters so the generator cannot earn reward merely by changing the predicate or a convenient proxy.
3. **Build a whole-scene step 5 probe on that worker.** Pair I and C on identical novel training programs at four and sixteen frames. Include pose/vertex work, tables, a branching folded march, a shadowed custom style and a raw-WGSL handoff. Count every fallback in the aggregate. My proposed investment threshold is **at least 2× completed samples per GPU-hour** at the same CPU allocation, with lower CPU-seconds per scored sample, reproducible same-tier hashes and zero unexplained reward flips on the corpus. Report median and p95 end-to-end latency. Claim 100 ms only for a specified workload that measures it. Add batching only after measuring queue/submission overhead, and promotion only after observing enough repeat draws to amortize it.

Start step 7 independently once each arm has a working authoring harness. Give the same model, token/time budget, cameras, revision opportunity and task-level judging rubric to every arm. Include collision, equation-driven motion, custom shading and a folded field. Keep the 10/12 decision per comparator, specify ties and failed builds in advance, and publish paired outcomes and authoring costs. If Loft loses, demonstrate one shared check on a three.js scene before promising the §8 fallback. A three.js mesh or shader needs geometry and motion the twin can actually read. Defer the rest of step 8 and the universal claims in step 9 until observed authoring failures or reward discrepancies identify the next capability.
