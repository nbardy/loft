## Presentation and encoding

2. In the selected native offscreen constructor, request the needed limits on Keel’s device before acquiring it. Keel’s `downlevel_webgl2_defaults().using_resolution(adapter.limits())` has zero storage buffers and zero storage binding size. Verify vertex and fragment storage support, and request at least three storage buffers per shader stage (two fixed runner bindings and the row) and at least 112 bytes for a storage binding. Keep Keel’s normal resolution/alignment and other renderer requirements. Report an unsupported adapter by name with its actual limits. Attach one runner per selected host renderer using clones of Keel’s wgpu handles and `HostCaps { depth_convention: StandardZeroToOne, msaa_samples: 1, features: … }` derived from enabled capabilities. Load once. Keel allocates one 112-byte `STORAGE | COPY_DST` buffer on that device, calls `bind_external_buffer` with its `Arc`, and writes the row once before each selected submit. Handle layout is seven little-endian, 16-byte lanes with WGSL-compatible alignment. Carry the ambient host inputs in the row so the shader can use the exact scene camera without a new Runner argument.

   | Byte offset | `vec4<f32>` components |
   | --- | --- |
   | 0 | camera origin xyz, focal |
   | 16 | camera target xyz, aspect |
   | 32 | clip-space jitter xy, history-active 0/1, zero |
   | 48 | core center xyz including push, radius |
   | 64 | core side xyz, zero |
   | 80 | core up xyz, zero |
   | 96 | display-encoded core RGBA |

With `w = dot(world - origin, forward)`, use `clip.z = (far * w - far * near) / (far - near)` and the same operation order as Keel where required for depth ties. Near is 0.1 and far 4096.
