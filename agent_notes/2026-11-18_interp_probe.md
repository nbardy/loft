# A register interpreter for Loft paint, 18 November 2026

## Prediction recorded before implementation or timing

Measure one full-screen evaluation at 512 × 512. Use the Reefback Titan's base carapace paint in its own (m,v) coordinates and the Maelstrom Wyrm's deformed, clear-water colour case in world coordinates. Use identical sample centres, time, camera facts and floating-point output on each backend. The latter case includes the whirlpool and style but excludes the nearby-body depth search. This isolates the cost of paint at known coverage. A scene camera would charge different numbers of fragments and mix in other stages.

One bytecode dispatch per folded, interned node, including leaves. Budget about **16–32 GPU instructions per lane per dispatch**: fetch/decode and branch, two dynamically addressed operand reads, arithmetic (more for vector or library ops), destination write and loop. At an estimated effective 250 billion scalar instructions/s, 24 per node gives 0.0252 ms per full-screen node. Budget ~65 nodes for the crab and ~280 for the water: **1.7 ms crab, 7.1 ms whirlpool**, vs **0.1 and 0.3 ms** compiled. Register spilling or serialization of the indirect loads could dominate this model.

**Kill the unpruned interpreter if either graph adds more than 10.0 ms per 512² paint frame** (least warmed interleaved time for each backend, same graph). Four training frames would then consume over 40 ms extra for one full-screen paint graph, already ~9% of the quoted 450 ms low-end setup saving. This is a budget for one stage, not a requirement that an isolated pipeline itself saves 450 ms. Correctness is separately required.

Time GPU work with timestamp queries. Amplify short measurements above the clock tick. Calibrate a scalar-lane FMA-equivalent rate with a timed arithmetic shader; multiply by seconds per pixel-op. This gives a throughput-equivalent cost, not a hardware retired-instruction count (waiting on memory also spends time). Measure module plus asynchronous pipeline creation in separate fresh processes on identical source, first for a new cache key and then after first use. Time lowering and upload through queue completion. If the budget is missed, the ideal retained op fraction is at most (compiled ms + 10) / interpreted ms before paying for a tile classifier.

## Result

**Both graphs pass the 10 ms test.** The interpreter added **2.00 ms** to the carapace and **5.49 ms** to the whirlpool. The whole-scene setup timings below show how much compilation the renderer does beyond these two paint functions. The probe measures the saving from replacing one function separately.

| 512 × 512, one fragment per pixel | Bytecode ops | Peak live vec4 registers | Code + constants | Compiled GPU ms | Interpreted GPU ms | Added ms | Max absolute RGBA error | Derived scalar FMA equivalents / pixel-op |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Reefback Titan carapace | 63 | 11 | 1,328 B | 0.0328 | 2.032 | 1.999 | 5.96e−7 | 57.6 |
| Maelstrom Wyrm whirlpool | 323 | 33 | 6,400 B | 0.0778 | 5.571 | 5.493 | 1.16e−4 | 30.8 |

**Measured setup, wall ms.** Paint module + pipeline columns are medians of three distinct fragment keys and their three exact repeats. The bytecode columns are medians of nine fresh allocations and lowerings in the warm process. The total is the median of the paired sums. The first lowering + upload took 1.33 and 1.36 ms respectively. One creation of the fixed pipeline took 105.9 ms on the measurement device, shared by both graphs.

| | Bytecode lowering | Upload through queue completion | Lower + upload | Paint module + pipeline, cold / warm | Whole scene modules + pipelines, cold / warm |
|---|---:|---:|---:|---:|---:|
| Carapace / Reefback Titan | 0.047 | 0.364 | 0.413 | 34.42 / 1.70 | 5,442 / 569 |
| Whirlpool / Maelstrom Wyrm | 0.167 | 0.387 | 0.569 | 51.52 / 4.57 | 3,274 / 313 |

**Four-frame sample, derived.** For just this paint at full coverage, switching saves 26.0 ms (crab) or 29.0 ms (water) when the paint pipeline is cold. With a warm Metal cache it costs 6.7 or 18.0 ms over four frames. The calculation is compiled paint setup minus bytecode setup minus four times added GPU time, with the fixed pipeline already resident. Credit for the whole-scene compile would require covering the other stages too.

**Per-tile interval pruning.** Both graphs meet the predeclared budget with zero pruning. To *break even on four frames with a warm cache*, the paint GPU budgets would instead be 0.355 ms and 1.079 ms respectively. Under an optimistic linear cost model, tiles must eliminate at least **82.5% / 80.6%** of interpreter time averaged over pixels, or retain about **11 / 63** and **62 / 323** equally expensive ops per pixel. Any tile analysis, tape construction and fixed render cost raise those requirements. Library ops have different costs, so the time fractions are the stronger statement. No pruning was implemented or timed.

## Inputs, instrument and numerical check

- `paint_titan` is the base scene's carapace paint over pixel-centred body coordinates in [0,1]². `colour_sea_2` is the production clear-contact, deformed-water fragment case, including the woodblock style. The sampling plane spans −10 to +10 in x and z at y = 0, entirely inside the radius-15 whirlpool. Both use t = 0.91 and the same 20-unit-high top-down orthographic camera. This prices the case wherever it runs. Actual game views also choose other water cases and have different coverage.
- Both roots come from `compileScene(...).programs`. The probe verifies rate lowering lifts zero nodes for these functions. The reference shader calls the function text extracted from the actual artefact with its library dependencies and Loft camera prelude. The interpreter lowers the folded root to a topological tape with one instruction per node including constants, inputs, constructors and swizzles. Loft's rate classifier counts 44 pixel nodes plus 19 constants for the carapace. The water case has 243 pixel nodes, four frame-rate nodes and 76 constants, all dispatched. The design notes' earlier ~280 per-pixel count included contact work.
- Each 16-byte instruction contains opcode, destination and up to three operands. The compiler recycles a register at its last use. Each fragment runs the same tape and switches on opcodes from read-only storage. This keeps `fwidth` quad-uniform. Known library calls, including hash and noise, use the Loft WGSL bodies. Unsupported operations, signatures, library definitions or register pressure raise `UnsupportedPaintOp`. The shader source is independent of the graph and the runtime uses one pipeline for both tapes.
- Apple M4, bun-webgpu/Dawn on Metal. GPU timestamp spans cover complete render passes into RGBA32Float. Three warm-up batches, then 15 interleaved rounds rotating graph order and direction. Short compiled measurements use 16 separate clear/draw/store passes per span, divided by 16. Each interpreted measurement uses one pass. Copies and CPU readback are outside frame timing. The 0.065536 ms tick gives the compiled batches 0.004096 ms per-frame resolution. GPU medians (compiled / interpreted) were 0.0369 / 2.359 ms and 0.0819 / 6.160 ms. An earlier run under different load gave best interpreted times of 1.966 and 6.685 ms. Both runs passed.
- `uptime` at the scored run's beginning and end: **13:01, up 7 days 48 min, 5 users, load 5.68 / 5.49 / 6.83** to **13:01, up 7 days 49 min, 5 users, load 5.32 / 5.42 / 6.76**. Compilation and frame measurement ran sequentially. The project test suite ran afterward.
- **Derived instruction cost.** Four independent vec4 FMA chains produce 16 scalar-lane FMA results per pixel per iteration. At 128 and 256 uniform-controlled iterations the same shader took 1.163264 and 2.310144 ms (least, four passes per timestamp span). The difference gives 512² × 128 × 16 / 1.146880 ms = 0.468 trillion scalar FMAs/s. Multiplying that rate by measured interpreter seconds / (512² × ops) gives 57.6 and 30.8 FMA equivalents. Aggregate times were 123 and 65.8 ps per pixel-op. These are throughput prices including dispatch, scratch traffic, library calls and render overhead. Timestamp queries cannot count retired Metal instructions. The numerical throughput price exceeded the predicted instruction range on the small graph, while the frame estimates were within 0.4 ms and 1.6 ms respectively.
- **Pixel agreement.** Every component of all 262,144 pixels was finite on both paths. RMS RGBA differences were 1.00e−8 and 1.30e−6. Every channel difference was below 1/255 before quantization. The whirlpool's worst pixel, red at (211,121), was 0.63911325 compiled and 0.63922912 interpreted. Reading intermediate results at that pixel traced a 9.54e−7 difference in the rotated material angle into a 4.68e−6 difference in the foam value (0.45469278 / 0.45469746). The cell hash agreed exactly. The woodblock foam edge applies a narrow smoothstep with half-width 0.023919 there. Its mask differed by 1.41e−4, which the final ink mix turned into the observed red error. The angle difference is consistent with compiled multiply/subtract contraction and f32 rounding across bytecode stores. The amplification through the mask was observed directly.
- **Cache conditions.** Each cold/warm measurement uses a fresh Bun process and device with an unrelated pipeline created first to pay driver startup. A never-taken uniform comparison with a fresh integer embedded in WGSL gives the cold fragment a new executable key. The warm process gets identical source; no process-local pipeline object can carry over. Order reverses between cold and warm and alternates between rounds. Measured cold/warm pairs (ms) were 34.42/1.70, 25.03/3.30, 51.65/1.52 for crab and 51.52/4.57, 84.98/3.28, 51.13/5.56 for water. Cache state is inferred from first use and cross-process repeats.
- The whole-scene column uses one such cold/repeat pair through the production host, timed from first module creation until the parallel pipeline batch and fixed bind groups are ready. The benchmark adds the uniform guard to scene-dependent entries. Both scenes reuse two frame-independent modules unchanged. Titan has 78 modules and 89 render + 19 compute pipelines; Wyrm has 48 modules and 58 render + 10 compute. This excludes JS scene import, graph build, WGSL generation and device startup. The bytecode clock likewise starts with the folded graph available and includes bind group creation, buffer writes and a queue fence. A complete bytecode version of either creature would also need its other paint, pose, geometry and post stages.

Run from the worktree with:

```sh
mkdir -p out/interp
bun tools/interp_probe.ts > out/interp/scored.json
```

The JSON contains every timing sample, paired setup measurements, register counts and worst-pixel coordinates. The graph extraction, bytecode, timestamp instrument and whole-scene setup instrument live under `tools/interp/`. The normal renderer and scene files require no changes.

Verification: a fresh run of the final harness gave 0.0328 / 2.097 ms for the carapace and 0.0778 / 5.439 ms for the whirlpool, with identical maximum errors. The typecheck passed. `pnpm test` passed all 222 tests across 59 files. A separate lowering check raised `UnsupportedPaintOp` naming `normalize(vec3)`.
