# Lane 1.2: the recorder (19 Nov 2026)

Plan: `docs/proposals/2026-11-19_lean_rust_loft.md` §3.2, §3.3, §8.1, §8.2 (lane 1.2). Branch `feat/lr12`.

## What

- `src/record/wire.ts`: the wire's numbers on the TS side. These are the op codes (`Op`, prims from `PRIM0 = 16` in
  `PRIMS` order), the `Ty` codes, the 11 decl tags with their word layouts, and `pack` (the header plus 11 spans as one
  byte string, used for the hash and for dumps).
- `src/record/recorder.ts`: the recorder. `Expr.fresh` appends every node to a log as the four node words, and
  `job(program, roots)` writes the part of the log the roots reach. The order is canonical: nodes are numbered by first
  use in a post-order walk, and decls, literals, symbols and resources by first reach. Loop and function binders are
  named by the number of the decl that owns them (`L3s0`, `F2a1`).
- `src/record/print.ts`: the canonical print. `printGraph` reads the TS graph (`Expr.node`), and `printJob` reads a job
  and inlines its calls. Both print hash-consed lines, with loop binders as de Bruijn levels. The grammar is in the
  file header, and loft-ir's printer must reproduce it byte for byte.
- `src/record/score.ts`: the lane's check.
  - `bun src/record/score.ts SCENE [--perturb SEED] [--dump F.job] [--print F.txt]`
  - `--compare SCENE...` runs each scene three ways: from source, perturbed (all library modules imported in a shuffled
    order, plus discarded expressions), and as a `bun build --compile --bytecode` executable.
- `src/expr.ts` (+12): records nodes in `fresh`, counts constructions, captures `emitWgsl` roots, exports
  `identitiesOn`, and wraps `replace` as a rewrite.
- `src/text/lower.ts` (+64): a text graph function is recorded once over binders, and each call as one `Call`. That
  happens only when every argument is a non-constant expression and no identities are open. Otherwise it is inlined,
  for a reason the classifier names: a bool or non-numeric signature, `gradient`, or a hole that holds a function or a
  record. The body is lowered only when a job is written. Lowering it earlier shifted every later `Expr` id, which
  broke the text-vs-call WGSL byte test.

Lines: 484 scc code lines in `src/record/`, plus 76 changed lines in expr.ts and lower.ts. The ceiling is 1,400.

## Left / integrator notes

- No registrations are needed in Cargo.toml, lib.rs or main.ts.
- loft-ir must decode per `wire.ts`. Points where this lane fixed the encoding, because §3.2 leaves them open:
  - `Swizzle` and `Vec` are ops 10 and 11.
  - `decls` starts with the program-root count. `roots` holds the program roots first, then each decl's roots in order.
  - In wave 1 a Kernel decl names a resource the TS compiler fills, either a table or rows. Wave 2 gives Kernel bodies.
  - A Fn decl is either graph or raw, and both `Call` and `Raw` index it.
- For the shadow check, the Rust print of `--dump` must equal the `--print` file. The script needs about 0.1–0.3 s per
  scene.
- Gaps in what the recorder writes today:
  - `sites` is empty and `siteOf` is all 0, so Rust refusals do not have the author's line yet.
  - `Grad` is not used, because derivatives arrive already expanded.
  - The JS twins of `LibFn`s are not carried, so lane 2.4 must move hot library functions to `graphFn`.
  - Roots are taken from `emitWgsl` only. `compileJs` roots (checks and CPU fills) are not captured.
- The log lives as long as the process, as the TS interner does. A long-running `loft dev` therefore grows. After the
  cutover, reset the recorder per program.

## Review (integrator pass, 18 Nov)

Re-measured on M4 (nice 10): `score.ts --compare` gives the same three hashes from source, perturbed and bytecode
(owl `1b1ac936ebb51368`, Titan `0b0eccc171dcf981`, heron_leap `08b60cf70a497c00`), with the prints equal. R
(loaded / designed / whole build / rewrite) is unchanged: owl 7,519 / 7,519 / 115,818 / 556; Titan 459,382 /
459,382 / 4,395,710 / 13,027; heron 108 / 66,763 / 283,726 / 10,152. Corpus: 124 of the 125 example files report
(71 built, 52 `LoadError` for library files that are not scenes, 1 `TypeError` in `serpent_clip`, which is
`scene.style` undefined in `src/compile`, not the recorder), and every print is equal. scc: 488 code lines (after these fixes) in
`src/record/`.

Fixes in the review commit:

- `wire.ts`: `PRIMS`, `TYS` and `ROLES` are checked against `Fn`, `Ty` and the table role at compile time, in both
  directions. Before, the recorder used `Map.get(...)!`, so an operator added to `Fn` but not to `PRIMS` would encode
  silently as op 0 (`Lit`). The recorder now indexes `Record<Fn, number>` and `Record<Ty, number>`.
- `lower.ts`: lowering a graph function over binders inlines its calls only on a `TextError` (an authoring refusal).
  Any other throw is a bug and surfaces. It had been caught and turned into an inlining reason.
- `recorder.ts`: a call nested in a recorded call's inlining no longer adds to R (`call` counts through
  `construct()`). None of the three scored scenes is affected.

Still open (not fixed here):

- `examples/second/heron_leap_refused.ts` refuses at module load with a `SceneError`. `score.ts` does not catch import
  errors, so this file produces no line, and the corpus is 124 of 125.
- `FnBody`/`done` encode "no body" as a string reason beside an object, not as a named variant. It is acceptable
  for wave 1, and wave 2 should make it a tagged union.

## Wave 1 integration: the shadow check does not pass (19 Nov)

On main after merging lanes 1.1, 1.3 and 1.2, `score.ts SCENE --dump F.job` and loft-node's `run` (lab build) give
`Internal(Wire{span: Args, at: 0, what: Bounds})` for owl, Titan, heron_leap and dust_veil. The TS half still
reproduces (hashes, R and print equality above). The two lanes filled the parts of plan §3.2 that it leaves open
in different ways, and both claimed to have pinned them:

| What | lane 1.1 (`loft-ir/src/wire.rs`) | lane 1.2 (`src/record/wire.ts`) |
|---|---|---|
| Span table | 11 × (byte offset, byte length) after the header | per span: byte length, 4 pad bytes, bytes padded to 8 |
| Symbols | `sym_ends`: end byte of each symbol | `symAt`: n + 1 start offsets |
| Op codes | 0 Lit, 1 Leaf (flags: time/param/input/bind), 2 Call, 3 Fetch, 4 Loop, 5 Grad, 6 Raw, 7 Swizzle | 0 Lit, 1 Time, 2 Param, 3 Input, 4 Bind, 5 Call, 6 Fetch, 7 Loop, 8 Grad, 9 Raw, 10 Swizzle, 11 Vec |
| Lit | n args = 0 | n = component count |
| Swizzle imm | len in bits 0..3, comps << 3 | comps 2 bits each, len << 8 |
| Binder | `Leaf::Bind(id)` | `Bind`, imm = name sym, flags BOUND/FREE |
| Raw | imm = source sym | imm = Fn decl ordinal (raw Fn decl carries the text sym) |
| Decls | fixed u32×4 `[tag | arity<<8, name, roots off, n]` | `[program root count]`, then `tag, n roots, n words, words...` |
| Fn decl | roots `[binder × arity, result..]` | words `[0, name, ret ty, n params, binder...]`, roots `[body]`; raw `[1, ...]` |
| Loop decl | roots `[count, init×a, binder×a, index binder, next×a, stop?]` | words `[n state, has stop, binders..., index]`, roots `[count, init..., next..., stop?]` |
| Kernel decl | name and roots only | words `[0, name, lanes, entries, role]` or `[1, label, rows off, len]` |

Lane 1.2's layout carries strictly more (kernel lanes/entries/role, Fn return type, program roots), so the cheaper
repair is likely loft-ir's decoder adopting it, with `Vec` added to `Op`. That is a lane-sized change to
`wire.rs`, its fuzz and fault tests and `layout()`, plus the Rust inline and canonical print that no lane owned
(lane 1.1: "the canonical print belongs to loft-core"). It should be one owner's job before wave 2's decode work
starts; the integrator did not attempt it. Until then lane 1.2's pass condition (Rust print = TS print over the
corpus) is open, and loft-node's `drive` stays the decode-only stub (loft-core has no program driver to swap in).
