## What

`rust/crates/loft-core/src/emit/{mod,body}.rs`: 658 scc code lines after rustfmt and the review fixes (ceiling 900).

- `module(g, exports, at) -> Emitted { text, reads }`: the Fn decls named in `exports` and every function they call,
  as one WGSL module, which Naga validates (f32 alias) before it is returned. `at` is layout's answer per decl (lane
  2.1): `[slot, 0]` for a Param (component slot) or an Input (vec4 slot) of the frame uniform, `[res, lanes]` for a
  Kernel. `reads[k]` is the kernel bound at `@group(1) @binding(k)`.
- `validate(g, m, f16)`: Naga parse + validate under `alias lf = f32;` or `enable f16; alias lf = f16;`, no GPU.
- **Names by first use.** Statements are `v0, v1, ...` in the order a walk from the result first needs them; loops
  take the next number too. A graph function is `f` + FNV-1a-64 of its own text, so it has one name in every module
  and job, and two decls with the same text are written once. Node and decl ids never reach the output.
- **Placement.** One pass over users-before-operands puts each statement in the deepest block holding all its uses:
  root, a `select` arm (the branch-local `if`), or a loop body. A node that reads none of a loop's binders is lifted
  out of that loop. Loops are written as the TS emitter wrote them (state `var`s, `for` capped by `u32(count)`, every
  next value read before any is assigned, then `if (stop) { break; }`), so picture parity is not at risk from the form.
- **Precision.** Generated floats are `lf`; frame and storage stay f32 and are converted on read. Raw author
  functions keep their own types: arguments are converted to f32 and the result back to `lf`.
- **Fetch** clamps the row by construction: `r{res}[min(u32(row), arrayLength(&r{res}) / lanes - 1u) * lanes + lane]`.
- **Site map.** Every module line records the node it writes, or (raw node, line) for copied raw source; a Naga
  refusal is `Scene { site, Wgsl { line, msg } }` at the node's site, or at the author's line inside a raw function.
  Each raw source is also parsed alone first, so a typo is refused even when nothing calls it.
- Operator spellings come from `prim::PRIMS` (lane 1.3); `vec`, `pick` (a chain of selects on `i == k`, as
  `src/expr.ts` defines it), scalar `normalize` (`sign`) and scalar `dot` (`*`) are written in emit.

## Left / seams for other lanes

- **Two `Prim` enums.** loft-ir's `Prim` (lane 1.1) and loft-core's `prim::Prim` (lane 1.3) have different orders;
  emit maps one to the other in one exhaustive `match` (`emit::core`). When the wire repair makes them one enum, that
  match goes.
- **Errors.** A Naga refusal of generated code is a Loft bug but has no `Internal` variant in loft-ir; it comes back as
  `Scene { Wgsl }` at the node's site, as §1.8 describes for author WGSL. Consider `Internal::Wgsl` when error.rs
  next changes. A function-name hash collision is not checked (64-bit FNV over at most thousands of functions).
- **Multi-result graph functions** (`Ty::Rec`) are refused as `Scene { Unsupported }`: loft-ir has no op that reads a
  record field yet. `Grad` reaching emit is refused the same way (interning, which rewrites it, has no owner yet).
- **Layout** (2.1) owns the frame uniform: emit writes `struct Frame { time: f32, params: array<vec4<f32>, P>,
  inputs: array<vec4<f32>, I> }` at `@group(0) @binding(0)` and kernel storage at `@group(1)`. If 2.1 picks another
  layout, change `module`'s first lines and the three leaf spellings in `body.rs`.
- Constant-only operators must be folded before emit (§1.10): Naga's constant evaluator refuses e.g. `log` of a
  negative literal. Under f16, literals beyond 65504 are refused by Naga.
- Recursion depth of `Body::need` is the longest dependency chain in a function; deep scene chains may need an
  explicit stack.
- The 63-scene Naga run, the real permutation hashes and the chunk-count comparison are this lane's open checks; run
  them once jobs decode and 2.1/3.1 supply entries.
