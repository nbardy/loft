## Your lane: fp16 where it is safe and fast (worktree `~/git/_wt/loft-f16`)

Everything is f32 today. WebGPU's optional `shader-f16` feature (Dawn and wgpu both expose it) gives f16 storage and
arithmetic; bf16 does not exist in WGSL. Apple/AMD/mobile run f16 ALU at ~2x; everyone saves bandwidth.
- Detect the feature at device creation (headless host, serve, viewer, and the Rust loader's `rust/loft-loader`).
- Use f16 where precision allows and say where it does not: colours, normals, paint channels, style terms, post
  passes, lookup tables (storage), volume/medium tables. Never positions, distances during marching, time, depth.
- One switch on the build/render (e.g. `precision: "f32" | "mixed"`), default decided by measurement; when the device
  lacks the feature, the mixed request is a named fallback recorded in the answer/manifest, never silent. Frames are
  then a function of precision too: record it in the determinism tuple (`loft serve` answers already carry `tier`).
- Measure: ms/frame and memory on 3 scenes (a creature, a pbr scene, a soft medium) f32 vs mixed on this Mac; max
  pixel difference. Keep the f32 path byte-identical to today.
