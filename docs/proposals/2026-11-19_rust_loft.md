# Loft's Rust compiler and headless host (19 Nov 2026)

Keep the scene language in TypeScript. A scene records typed operations and where to use their results. Rust owns the
graph that gives those operations meaning, the CPU twin, proofs, motion solving, WGSL generation, table and pass
planning, and artefact writing. Use native Rust through Bun FFI for compilation and wgpu 30 through
`rust/loft-loader` for the headless draw worker. The compile child stays GPU-less. A game still loads a directory on
its own device. The first change makes emitted names independent of allocation order and establishes the byte
baseline used by every subsequent lane.

The current Rust core moved two kernels behind `LOFT_CORE=rust`. It cut heron peak RSS from 1,106 to 236 MiB and
Titan CPU from 2,128 to 1,475 ms. Titan still constructs surface graphs at 25 rest points and runs the table bodies
during compilation. Moving today's compiler behind a native call after `draws` would pay both bills. The port starts
by making that work expressible as recorded inputs. [Rust core note](../../agent_notes/2026-11-18_rust_core.md),
[compiler measurements](../../agent_notes/2026-11-18_rustplan/NOTE.md),
[authoring API](2026-11-18_authoring_api.md).

## 1. What the author records

The scene still imports the same functions and types. Call form, fluent expressions and swizzles, `wgsl` functions and
holes, `scene`, `design` variants and style replacement, the draw and compute primitives, `always`/`eventually`,
`equal`, and `solve` keep their signatures and meanings. The suite should build the same examples through those
entry points. A paint can still destructure its arguments, use JS control flow over ordinary options, call other
functions that make expressions, and return a shaded record. TypeScript can calculate ordinary authoring values
such as array lengths, names, or a layout made from plain numbers. An `Expr<T>` is a typed handle to a recorded
operation. Its identity as a JS object is useful for tracking that handle. Structural equality, including separately
written equal expressions, is determined by Rust. Audit library uses of object identity, `.node` and `.id` before
changing the representation. Literal/type inspection used for input validation can read a record. Graph analysis
used to pick shader code becomes a request to Rust.

Allocate a recorder for one loaded scene and selected variant or style. Store a node as four little-endian u32
words: packed opcode/type/flags, offset of its operands, operand count, and an index or immediate payload. Append
ordered operand IDs to a u32 stream. Put numeric literals and defaults in an f64 stream, f32 row samples and supplied
binary assets in spans, and symbols and original source sites in side tables. Use growable typed-array blocks with
used lengths. An ID indexes a record within the job. Static library values used across jobs must be imported as
descriptors or recipes with fresh handles. Use dense tagged descriptors for loops, tables, functions, renders,
compute, post and check requests. A render descriptor carries ordered shader templates and typed holes for
function bodies, table/row access, resource slots and generated constants. Move invariant compiler-owned template
fragments with their emitter as each draw family ports. Author source text, explicit raw names and dependency lists
travel as data. For example, `CompileContext.table` gives a table reference during recording. Slot allocation, WGSL
declaration text and capacity checks run in Rust. JS records the order in which the drawable wanted the references.

Callbacks run with typed symbolic binders. The style and surface functions record ordered result roots for their
consumers, including separately declared rest, draw or paint roles where signatures differ. A shared role with the
same formal arguments can reuse a recording. A map records a body once per run with its local index. A scan records
initial values, the index and state binders, the next tuple and the vec4s written each step. An `iterate` records the
count, init, binders, next tuple and optional stop evaluated on the next state, in that order. Rust computes the
loop's inner and outer dependencies. A rewrite substitutes a capture-avoiding binder mapping in the recorded
body. Today `replace` and `fold` call the saved step again. Port their reachable behavior with nested loops,
invariant captures and simultaneous state updates covered explicitly. Treat symbolic chart substitution,
`gradient`, and library derivative definitions the same way: record operands and binders, then transform in Rust.

Reachable descriptors are recorded in first-demand order. The recorder follows references to find further bodies
that need calling, keeping declaration state for mutually referring descriptors. Rust decides which programs survive,
whether a table cycle is legal, which reads depend on the frame, and which bind groups and dispatches to allocate.
Preserve the present phase and declaration order where it affects slots or the first error. Validation of an unused
definition must have the same observable effect as before. Record source sites and operation ordinals separately
from intern keys so equivalent expressions can have different diagnostic sites.

`wgsl` stays a TypeScript parser and front end. At a graph function call it binds actual expression handles, lowers
locals to SSA values, branches to selects, and bounded loops to the same binder and tuple records as call form.
Records returned by a shader function become JS records of handles. Resolve holes and prelude names in TS and keep
the source span of each expansion. Keep front-end constant work needed to interpret the source language, such as
deciding the type of an abstract integer or handling a statically known array shape. When an operation has an
expression as an input or result, record its arithmetic and the applicable construction-time identity rules, then
let Rust fold it. WGSL ties-to-even round and truncated remainder keep their own opcodes. A raw function crosses
as text, signature, dependencies, hole handles and its GPU-only reason. Raw draw and compute entry points use the
same representation. Rust writes hidden arguments, accessors and bindings. A raw function calling a graph function
gets a generated function from recorded formal roots, including any declared captures. It needs no JS emitter callback.

Today's constructors do more. `gridDetail` builds 25 copies of a graph. Record one surface over symbolic grid
coordinates plus the exact five-by-five points and anchor convention. Rust substitutes each point first for the
initial parity implementation. The old callback can recognize a literal argument, so run this conversion first on
library surfaces whose symbolic substitution reproduces that path. Pass any exceptional specialization through
an explicit recording of the old roots until it can be expressed in the same IR. Use a 25-lane tape only once the
old specialization and batched path agree in bits, including the resulting lengths, radius and artefact values.
Default PBR environment projection, sun defaults, field safety and rest meshing, static tabulation and `castRay`
colour estimates similarly become build requests with expression roots and explicit sample or geometry recipes.
Keep their caller-visible validation. When graph values choose topology, Rust expands the recorded geometry
recipe using those values. Libraries that use numbers merely to compose a recipe, such as the ship hull's mast
positions, can often compose expressions straight through. Audit actual scalar consumers before changing a
constructor.

## 2. Handoff and compatibility

Use a versioned packed wire and a single synchronous native execution per complete program. For the scene build,
Bun passes a directory of used typed-array spans, ordered command roots, compiler options and the output target.
The Rust job validates bounds, tags, references, symbol scopes and quotas before graph passes, borrows the input
only for the synchronous call, and writes the artefact under the same confinement as the child. Return a compact
result and typed diagnostic or requested inspection data. The existing call/take pair is a valid first transport
with one engine invocation and one payload copy. At the scene writer cutover, use one C entry that writes into a
bounded caller-owned status buffer, with any large requested result written to a caller-supplied job file. A small
version handshake at library load is outside the per-program path. `compile(scene)` and other in-memory consumers
can use one call/take transaction for an owned result, then wrap data and Rust operation handles in the existing
public types. No per-node FFI, evaluation callbacks into JS, borrowed result across calls or Rust pointers in author
objects. Use an explicit owner and release for any reusable native tape. Debug capture writes the input format that
the replay tool accepts. Return readable wire errors and panics as internal errors and missing or stale libraries as
environment errors. Source names, stable site records and structured refusal payloads restore the same CLI exits.

A program is a closed unit of work with enough inputs for Rust to finish. The normal build records once and calls
Rust once. A synchronous `solve()` is its own closed program because it returns a report and can throw before the
caller continues. An explicit `evaluate()` reading a JS number is likewise its own program. A placed tool's
`compileJs` compatibility wrapper binds a reusable Rust tape and submits evaluations, batched where the API
already exposes multiple points. Author scripts and tools can branch on an explicit read. There is no way to
promise one native execution for that entire arbitrary JS module and also return the value before the branch.
Keep those explicit reads compatible and count them separately. A recorder callback must produce graph and
descriptors. Migrate any library callback that needs numbers to a deferred build request before enabling the
recorder for it. For a default heron build budget one solve transaction and one scene transaction.
GPU baking, when explicitly requested, consumes and completes the build recipe as a host operation.

Choose Bun FFI over wasm. There is already a working cdylib and replay binary. Native can borrow the typed-array
spans and call the same platform math as the pinned Bun twin. Wasm has no standard instructions for functions such
as `sin` and `pow`. A bundled libm needs its own bit proof and importing the host functions adds crossings inside
the numeric loops. Typical separate wasm linear memory also needs staging the recorder input. Wasm's portability
would matter for compiling in a browser, but the viewer can ask its local project server to compile into files and
keep its browser WebGPU renderer. Pin the Bun release and shared-library ABI on Linux and macOS. Bun documents FFI
as experimental, so keep the ABI transport shallow and replace the shell with Node-API if the Bun pin fails its
stability gate. Keep wgpu out of the compiler's link closure. [Bun FFI](https://bun.com/docs/runtime/ffi),
[WebAssembly numerics](https://webassembly.github.io/spec/core/exec/numerics.html).

## 3. Rust graph and arithmetic

Decode in dependency order and intern into a dense typed arena backed by compact child spans. Preserve ordered
children, literal bits and semantic resource identity. Audit the old interner's SameValueZero treatment of scalar
literals, retained representative sign and string keys for vectors before freezing their replacement. Same-valued
rows, different table objects, coincident parameter spellings and fresh loop binders are distinct where the current
contract makes them distinct. Track live roots explicitly. Scratch arrays indexed by arena ID handle traversal and
memoization. Use full key equality after a hash match. Hash iteration order never supplies output order. Slot
binding, rate selection and lifting, table dependencies, pass discovery and final emission use the same ordered
roots and bind scopes as the TypeScript reference. Raw shader text remains opaque except at the existing binding,
dependency, validation and sharing seams.

Carry three arithmetic contracts through the same operation definitions. The CPU twin uses f64 semantics, including
JS's vector component order, number-to-int rules and its existing expression identities. Build folding rounds at the
same f32 points as the current shader path. Table writes and curve controls preserve their encoded f32 boundaries.
Match literal printing, signed zero, NaN handling, library math and state initialization. For example, the existing
`jsmath::pow` prevents LLVM from substituting `exp2`, which changed 766 of 400,000 probe results. Test CPU bits per
pinned OS, including JS library helpers such as scaled `hypot`, and keep exact manifest number spelling, field order
and omitted fields. Preserve leftmost scanner behavior and text encoding in shader sharing, including the edge
cases currently refused by the Rust scanner. Never turn a library swap, stale native binary or unsupported operation
into a quiet compiler fallback. [Existing math and sharing probes](../../agent_notes/2026-11-18_rust_core.md).

Extend `tape.rs` from the solve kernel into a compiled scalar-register interpreter with lanes of independent
samples. Add bound inputs/params/rows, table fetch and loops. Keep scans sequential within each scan. Preflight
reads in the old order, preserve indexing and out-of-range rules, and surface the first error in original point
order when tiling pure work. Port trusted CPU library functions by registered identity or by a recorded graph body.
For author-level extensibility prefer a graph function that already has both meanings. Arbitrary `LibFn.js`,
`FilledTable.prepare` and imperative `Check.run` functions cannot cross the boundary as code. Port shipped
behaviors into graph programs or Rust operations, and preserve the existing file-build refusal for opaque fills
such as Storm. An external opaque CPU extension receives a named unsupported extension error on the new path.
Its JS reference remains available during migration. The stable model-facing vocabulary is intact, while the
low-level arbitrary-JS hooks have an explicit migration boundary.

Port affine interval evaluation before the ranged scheduler. Keep three-valued truth, bounds on f32-stored table
values, nested quantifier dependencies, traversal and witness tie order, search budgets and refusal reasons for
opaque reads, recurrences and unsupported codomains. Port built-in sampled checks as typed measures or domain
operations, including the skin search, probe geometry and budgets. A sampled pass reports its sample scope even if
the twin happens to evaluate all requested points successfully. `check` and explanation requests use the same
graph source map. Compare bounds, witnesses, accounting and failure kinds as well as the displayed verdict. Time
limits need a controlled clock in differential tests and separate real-deadline tests.

For `solve`, record `hold` against symbolic unknown curves, with the explicit `equal` mark, source, condition and
time quantifier. Use that hold graph for both jet substitution and substitution of the returned f32 spline
representation. Keep checks as expressions over the returned curve handles. JS currently calls `hold` again with
materialized curves. The documented pure hold must give the same list and windows under these substitutions.
During migration record both paths in the reference and verify their normalized graphs, window order and refusals.
A hold that depends on JS side effects or inspecting the representation of a curve needs to become a function of
the supplied curves. Rust owns classifying conditions, derivatives and Hessians, preference quadrature and start,
the conflict certificate, the existing numerical rounds and peak search, and final f32 verification. Cache only
verified solutions under a key that includes semantics, ordered holds, defaults and row content. On a hit restore
the documented zero steps, samples and rounds with current sites. The parity fixture requires the base and moved
heron control bits, 309/402 steps, four rounds each, 394/390 samples and each hold's peak value and time, plus the
ranged verdicts on the returned holds. Sampled solver verification and ranged proof remain distinct operations.

## 4. Cost and peak memory

The two measurements have different uses. Instrumented TypeScript build CPU on the shared M4 was Owl/Titan/heron
627/3,872/4,108 ms. Its exclusive graph scopes were 168/1,274/228, lower plus emit 142/1,295/192, tables
153/853/219, and heron's solve 3,323 ms. The later alternating uninstrumented runs put the current partial-Rust CPU
at 286/1,475/791 ms and RSS at 152/492/236 MiB. Titan's later sampled main thread put 27% in rest expansion, 13%
in table declaration/classification and 9% in the CPU twin. Those scopes include work across different phases
of the older run. Use them to locate work, without adding sample shares to process CPU. The 58 ms heron Rust replay
is the best of 20 and the 28 ms Titan share kernel is a warm measurement. [Phase notes](../../agent_notes/2026-11-18_rustplan/NOTE.md),
[partial-port timings](../../agent_notes/2026-11-18_rust_core.md).

The assumptions below predict a cold GPU-less build with a bytecode library, default variant, no cache hit and
rest sharing. Let U be the observed created-node count, around 16.4k/182.9k/39.8k. This includes today's
intermediate work. Treat U as a sizing proxy for distinct Rust nodes, not a measurement of live arena size.
Assume R recorded nodes at 4U/6U/4U, rounded to 66k/1,097k/159k. The observed 176k/6.28M/449k interner entries
include repeated validation, literal lifting and compiler rewrites. They are neither final node counts nor a
count of messages. The port must remove the repeated rest instantiations for the R assumption to hold. Use a
byte-volume proxy B = 0.5/3.54/0.6 MiB for sharing and writing, to be replaced by distinct scanned and written
byte counts. These B values are sizing assumptions, with Titan at the earlier study's large-artefact scale.

| Phase and assumed CPU cost | Owl ms | Titan ms | Heron ms |
|---|---:|---:|---:|
| Bun, native load and trusted bytecode, 10 + 7 + 15 ms | 32 | 32 | 32 |
| Scene module link and top-level work outside recording, allowance | 8 | 20 | 10 |
| Callback overhead plus recorder, 12/32/20 ms plus 100 ns/R | 19 | 142 | 36 |
| Handoff, 1 ms plus 28 bytes/R at 5 GB/s | 1.4 | 7.1 | 1.9 |
| Rust decode and interning, 35 ns/R plus 25 ns/U | 2.7 | 43 | 6.6 |
| Rewrite, fold, bind and rate planning, 8 visits/U at 24 ns | 3.1 | 35 | 7.6 |
| WGSL emit, 2 emitted statements/U at 55 ns | 1.8 | 20 | 4.4 |
| Descriptor lowering and shader sharing, 2 ms plus 8 ms/B | 6 | 30 | 6.8 |
| Layout, rest and table fills, 3 ms plus 2 visits/U at 20 ns and 8 scalar evaluations/U at 8 ns | 4.7 | 22 | 7.1 |
| Manifest, hash, writes and CLI, 3 ms plus 3 ms/B | 4.5 | 14 | 4.8 |
| Solve, 70 ms rounds and verification plus 12 ms setup/derivatives and 5 ms recording/transfer | 0 | 0 | 87 |
| **Projected total, rounded** | **83** | **365** | **204** |

The scalar rate prices a mix dominated by arithmetic, with transcendental or irregular fetch costs exposed as
separate counters. Eight evaluations per U is a proxy for executed scalar instructions across all rest and table
lanes. It excludes solve. The byte-rate term deliberately prices Titan sharing close to the measured kernel.
Source import adds roughly 55–65 CPU ms in place of bytecode savings. A trusted warm process could avoid another
32 ms of setup if it reuses all three startup components. Production still pays process setup until confinement and
job reset are demonstrated. Every extra 100k recorded nodes adds about 14 CPU ms for recorder, transfer and
ingest. At the old 6.28M entry count, that sensitivity alone would add about 730 ms to Titan. On these assumptions,
cold Owl and Titan exceed the old 50/150 ms goals, and heron fits its 250 ms goal.

Size worst overlap as 60–80 MiB for Bun and loaded modules, 5–10 MiB for Rust runtime and fixed metadata,
36 bytes/R of recorder capacity including growth slack, 16 bytes/R of live JS handles, and 88 bytes/U of arena,
intern index, remap and traversal scratch. Allow three times B for text, sharing and output, plus 4/16/32 MiB of
numeric and table scratch. In heron the latter can hold a 65,536-register by 32-lane f64 tile (16 MiB) plus 16 MiB
for solver arrays and other working data. Those are limits to measure against. Retire unused handles and free
sections at the last reader before opening output staging. The conservative sum is about 75–101 MiB Owl,
161–187 MiB Titan and 110–136 MiB heron, even if the solve and scene buffers overlap. Four Titan children size at
about 748 MiB before the GPU worker and file cache. Measure aggregate resident memory separately. At Titan scale
doubling R adds about 54 MiB before any extra arena growth.

Before scoring the forecast, capture raw and unique nodes, live handles, edges, per-pass visits, emitted statements,
registrations and slots, scanned/written bytes, tape instructions by opcode and lanes, sampled evaluations, and
solver slice sizes. Pair source TS, the existing partial core, and the full Rust path in fresh confined children
on macOS and target Linux. Compare process CPU and peak RSS, record native phase time and allocation peaks, and
report wall medians and p95 separately. Run Owl `game`, Titan `game` and heron `side` at fixed concurrency, then
the distinct generated training cohort. Score all phase assumptions in the first paired run. Investigate a count
miss before tuning its per-unit rate. Report GPU device startup, pipeline creation, frame and readback separately.

## 5. Module order and parity

Freeze the sorted 124 paths from the existing corpus driver on this branch. Its known split is 63 successes and
61 non-successes (52 exit 3, four exit 6, four exit 4, one exit 1). Run each through both entry points after
every lane lands. Compare the complete path set and the raw bytes of `manifest.json`, `bin/` and `wgsl/` with full
SHA-256 over names, lengths and contents, plus a first difference on mismatch. Compare complete verdict lines and
typed kind, payload, site and exit code where a typed outcome exists. The untyped exit 1 remains in its existing
class. Ignore explicitly volatile wall-duration fields only in report comparisons. The current driver truncates
digests and verdicts, so extend it in the first lane. Every row below adds a focused gate to this same corpus gate.
Keep a frozen TS oracle at the new naming baseline and a common fixture for canonical ordering. A lane can run in
shadow and leave production output on the prior path, but must demonstrate equality of the intermediate values it
claims to replace and of full bytes via its integration seam.

The naming lane is a single deliberate byte-baseline change. Number generated locals by first use in the existing
ordered emission walk, with stable helper and loop scopes. A shared chunk gets its own stable function scopes
independent of which module includes it. Seed names
from explicit bindings and reserved generated prefixes. Keep the emitter's `pre` aliases and output references.
Audit IDs escaping through helpers, lib names, table identities and slot or sort tie-breaks. Compare old and new by
renaming generated identifiers in parsed/tokenized WGSL and checking every module, pipeline and leaf association.
Only generated identifiers and directly derived chunk names, hashes and program identities may differ. Binary
files remain equal. Compare same-device pixels. Freeze the new full digests once reviewed. From that point, import
permutations, extra discarded expressions, CJS bytecode versus source and A/B/A jobs must hit those full digests.
The bundle needs a single library module identity for scene imports and original source locations for diagnostics.
Warm jobs also need fresh author modules, registry state and resource limits. Try the bundle in a fresh confined
child first. A warm process for trusted replay can establish headroom before deciding whether a clean single-job
boundary is feasible for author input. [Bun bytecode](https://bun.com/docs/compiler/bytecode).

Each row is one gpt-6.2-sol lane, with only the named slice and its fixtures. Parallel rows within a wave own
disjoint files or new directories. The integrator alone owns common Rust module declarations, Cargo wiring,

before the combined full suite. Make an earlier split at a supported variant boundary if its focused gate cannot be

## 6. Serve and the long-term split

Move headless `loft serve` drawing to wgpu 30. The game pin already has a loader, camera/frame writes, replay and
pose execution, pass scheduling, precision selection and pipeline warm-up. Reusing those is the payoff. The Metal
proof measured a consistent 8–14% GPU slowdown in comparable runs and small CPU encode savings. It also found
64/294 earlier modules Naga refused and 0/407 after f32 rate folding. This decision buys common execution and one
place to fix format behavior. It carries no frame-time speedup assumption. Use Vulkan's supported driver pipeline
cache keyed by adapter/driver compatibility, and in-memory caches on Metal. [Loader proof](../gpu_native.md#rust-loader),
[wgpu 30 pipeline cache](https://docs.rs/wgpu/30.0.1/wgpu/struct.PipelineCache.html#implementations).

Keep the Bun supervisor's JSON-lines contract, fresh confined compile child, slot limits, deadlines and request
routing. Replace its draw child with a warm Rust process that receives validated requests and directory paths, uses
the loader on its own device, and writes tightly packed RGBA files. Reuse the headless viewer's readback and
`Bounds::Latest` so a request's LOD depends on its own frame. Carry camera, input/param checks, precision fallback,
time order, byte caps, file validation, the trusted `--check` hook, transient device retry, crash disposition and
cleanup across the transition. Port the existing bounded folder reader's checks before it handles submitted
artefacts. The current Rust reader assumes game-owned files. Preserve the current refusal for incomplete GPU-less
bake directories. For offline builds, migrate baking on the same recipe and verify its output against the incumbent
producer before changing the default. GPU-derived bytes need a separate gate on the pinned producer and device.

Run every assembled module and pipeline through both validators during migration. Test identical source/files and
repeat requests on each backend, including mixed and f32 fallback, compute and replay. Require repeat RGBA hashes
per device/runtime. Backend swaps record the actual runtime and driver in frame identity, so cross-backend pixels
get a separate comparison. On matched cameras, times and sizes, require preserved detail plans, fewer than 0.01%
of pixels with any channel error over 8/255, no such connected cluster over four pixels and no shift across a
region. These thresholds come from the Metal proof. Measure them again on current scenes, then score target
Linux/Vulkan at matched workloads with an initial ceiling of 25% p95 GPU frame regression and separate cold
pipeline and end-to-end serve timings. Keep Dawn as the headless reference until those gates pass. Browser
presentation can keep its WebGPU host on the same files.

TypeScript permanently owns scene module loading, scene and library composition, the authoring types, the text
front end, source capture, recorder, explicit native-call wrappers, and the CLI/request supervision that needs Bun.
The compiler, CPU math and domain analyses have one production owner in Rust. The JS implementation is the
differential oracle through parity, then a pinned historical reference. The biggest remaining risks are numeric
drift across platforms, hidden author-side demand for numbers, changes to first-refusal order, raw shaders diverging
between validators, and temporary duplicate memory while both engines run. Treat each as a release gate at its
seam. The arena, tape, scoped graph lowering, native math shim, file format and loader build on Loft's existing
work. The proposed boundary adds a recorded symbolic body and explicit build requests, so a compiled scene can
finish without re-entering its authoring language.
